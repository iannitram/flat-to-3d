# Spec

**1.0 means:** I plug the Quest 2 into the Z13 and press **Play** on one of six Favorites in Steam (Game Mode or Desktop Mode): STAR WARS Zero Company, ACE COMBAT 7, Control, 007 First Light, Spider-Man 2 or Alan Wake 2. The 3D link over WiVRn comes up by itself, and the game plays in true stereo on a giant fixed 3D TV in the Quest 2, gamepad in hand, at 30+ fps. Unplugged, the same Play button plays it flat. A Decky panel and a small native Rust desktop app (iced) show the link, headset health and a 3D switch per game; there is no Inject button. Order, by readiness (ruling 46): Zero Company, ACE COMBAT 7, Control (Geo-11), 007 First Light, Spider-Man 2, Alan Wake 2. True stereo means two real views; alternate-eye rendering counts only for a game with no two-real-views route, at 30+ fps per eye (ruling 44).

**Approved by the owner:** 2026-11-11, the owner, the question tool: "Approve (Recommended)" for the spec with the six-game list and the rulings from the same question set (rulings 43-47 in `docs/notes/DECISIONS.md`): alternate-eye rendering "Yes, where nothing better exists (Recommended)"; Forza Horizon 6 "Move it to after-1.0"; order "By readiness (Recommended)". The list itself is his ruling of the same day, made while looking at his Steam Favorites: "This is the 1.0 list." (ruling 43). Changes this approval covers: M23 and M33 moved out, M30 reworded, M31 and M32 added with the routes research recommends (planned, untested).

**Ruling 42 (2026-11-10, written into the docs after the approval above):** Flat to 3D and Quest Tether stay separate apps, and the internet tunnel leaves 1.0. ## Problem

Installed PC games only play flat. The free VR mods that exist steer the camera with the head, which isn't wanted. True stereo on a fixed screen needs a per-game port, and nothing launches it from Game Mode.

## Solution

Run Zero Company and ACE COMBAT 7 in stereo through UEVR (our own hook if UEVR can't on Zero Company), Control through Geo-11 plus an SBS screen viewer, port SpidyVR's stereo-screen core to Spider-Man 2, switch on 007 First Light's dormant stereo mode and hook Alan Wake 2's camera for alternate-eye stereo, both through a proxy DLL of our own into the same SBS viewer (planned, untested), then wrap all six in one Rust engine that makes 3D disappear into Steam ("Plug in and play", 2026-11-01): a link service that brings the WiVRn link up when the headset is plugged in (the headset's internet link stays Quest Tether's job, a separate app, ruling 42), and a launch wrapper on each 3D-ready game that plays it in 3D when the headset is there and flat when it isn't. A Decky panel and a small native Rust (iced) app show the link, health and per-game 3D switches.

## User stories

1. As the owner, I want to sit with a controller and play my Favorites (Zero Company, ACE COMBAT 7, Control, 007 First Light, Spider-Man 2, Alan Wake 2) on a giant 3D TV in the Quest 2, so that the game has real depth without head-steering.
2. As the owner, I want to plug in the headset and press Play in Steam as usual, so that 3D needs no extra step, no terminal and no separate launcher.
3. As the owner, I want the headset's temperature in view, so that it doesn't throttle without warning. (The headset's internet over the cable is Quest Tether's job, not this app's, ruling 42.)

## Implementation decisions

- The rulings in `docs/notes/DECISIONS.md` are binding: Z13 and SteamOS only, true stereo only, a giant fixed TV, WiVRn (Quest Tether is a separate app, ruling 42), 30+ fps, offline only, free only, Spidy as the baseline, plain OpenXR.
- Controls: a gamepad through Steam Input for every game (ruling 2026-10-31).
- Control is the one Geo-11 game in 1.0 since ruling 43, and it takes the first Geo-11 test (G1, #43) that Planet of Lana had. The SBS viewer stays in 1.0: it serves Control, 007 First Light and Alan Wake 2.
- 007 First Light and Alan Wake 2 take the routes their research notes recommend (one note per game under `docs/notes/research/games/`); both are planned and untested. Alan Wake 2 is not a Steam game, so how its recipe is keyed and how it gets the launch wrapper is an open design problem.
- Alternate-eye rendering (ruling 44, 2026-11-11, question tool: "Yes, where nothing better exists (Recommended)") counts as true stereo for 1.0, per game, only when no two-real-views route exists for that game; the 30 fps bar then applies per eye.
- Geo-11 games need an SBS screen viewer that puts Geo-11's side-by-side picture on the fixed screen. Likely route, unproven: a viewer running in the same Proton session (OpenXR through WiVRn) reading Geo-11's shared texture, as Blackskydk/FlatToDepth and artumino/VRScreenCap (MIT) do on Windows.
- ACE COMBAT 7 is not installed today (its library drive isn't mounted).
- Zero Company comes first (ruling 2026-10-31): offline check, UEVR nightly under Proton, the 3D TV, then its recipe; it proves the headset chain and wrapper route on a real game while the Spider-Man 2 address mapping goes on.
- The Spider-Man 2 port follows `docs/spiderman2/plan.md` Steps 0-8. Its code lives in `games/spiderman2/`, and the DLLs build on the Z13 with clang-cl + xwin (ruling 21).
- **Two faces, one engine** (rulings 2026-10-31, question tool: "Desktop app + Decky plugin (Recommended)"; the toolkit rulings of 2026-11-01, question tool: "Native Rust GUI" with "iced (Recommended)" and "Rust backend, thin TS panel (Recommended)", replace "Tauri (Rust + web UI) (Recommended)"): the iced app links the engine crate; the Decky plugin's backend is the engine binary called with `--json`, and its TypeScript panel has no logic. Every word, colour, sort order and rule the faces show is an engine function. Shape: `docs/code-map.md`.
- **Plug in and play** (rulings 24-38, 2026-11-01; ruling 42, 2026-11-10): Steam is the launcher. A systemd user unit `flat3d-link` runs `flat3d-inject watch` (adb device tracking; no root once Flat to 3D's own udev rule is installed, ruling 42) and owns the 3D link: WiVRn, `adb reverse`, health. The launch wrapper `flat3d-run` asks it whether the link is ready and reads the game's 3D switch, then applies the recipe's route (UEVR, Geo-11 or the port) and execs `%command%`, or execs it unchanged. Flat to 3D has no tunnel and no gnirehtet; Quest Tether stays a separate app that it may only read (ruling 42). Only `works-now` games get the wrapper in 1.0.
- **The engine is Rust** (the owner's ruling, 2026-10-26, question tool: "Rust"): one binary, `flat3d-inject`, one Cargo workspace; engine `crates/engine` (package `flat3d-inject`), serde + serde_json plus the workspace's `flat3d-viewer` crate. The Decky plugin has no Python backend (2026-11-01: "Rust backend, thin TS panel (Recommended)"); the Spider-Man 2 port stays C++ on SpidyVR and the research tools stay Python (2026-11-01: "Leave them as is (Recommended)"). Rai Pal's game detection (Rust, GPL-3.0) is the reference for detection logic.
- **Recipes are a data file in this repo** (the owner's ruling, 2026-10-26, question tool: "Data file in the repo (Recommended)", #15), under `recipes/`, versioned with the code and read by the engine. For 1.0 the engine needs the six games' recipes; the owner's per-game notes elsewhere stay notes.

## Testing decisions

The engine is tested without games or hardware, with `cargo test --workspace` (Rust `#[test]`s and inline fixtures in `crates/engine/tests/*.rs`): Steam library parsing on sample `libraryfolders.vdf` and `appmanifest_*.acf` files, recipe loading, and the commands Start 3D would run (asserted, not executed). Every port step has its own on-device test, as in `docs/spiderman2/plan.md`.

## Further notes

For a local readiness report, run `flat3d-inject doctor`.

Platforms (R04): Linux (SteamOS) as the host only. The game DLLs are Windows binaries cross-built on Linux and run under Proton. Mac and Windows hosts are out (rulings 1, 2).
