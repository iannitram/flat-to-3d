## 4. Work packages

### Index
Waves: w0 = 00; w1 = 01a → 01b → 01c → 01d (in this order), 02, 25a; w2 = 03-07, 11-14, 16-18, 20-24, 25b; w2b = 35 → 36 → 37 (after w2, before w3); w3 = 08, 10, 15, 19, 26, 27, 28, 30; w4 = 09, 29, 31, 32, 33; w5 = 38; w6 = 34. WP-10 is merged and superseded by ruling 42. WP-39 is after 1.0, in no wave.

Each row matches its WP file: `files` is the WP's Files block, `depends` its "Depends on" line, `closes` its Closes/Refs lines. "refs" means the PR writes `Refs #N`, not `Closes` (ruling D5, §2 "PR and issue rules"). If a row and its WP file disagree, the WP file wins and this row is fixed.

**WP-01 is four rows.** WP-01a, WP-01b, WP-01c and WP-01d run in that order inside wave 1; each depends on the one before, and they share files (each part's file says which lines are its own). They are the one exception to "a WP never depends on a WP in its own wave" and to "WPs of one wave own disjoint files". WP-02 and WP-25a run in parallel with the chain: they depend only on WP-00 and need none of the four parts. In any `depends` below, **`WP-01` means all four parts merged** (WP-01a, WP-01b, WP-01c and WP-01d). `WP-01.md` is a pointer file with no row.

`depends` and the gate scripts: from wave 2 on, every done-check runs `tools/check.sh`, and some run `tools/locked-test.sh`. Both come from WP-02. The §0 wave gate covers that (all of wave 1 is merged before any wave 2 branch is cut), so a row does not list WP-02 for those two scripts. A row lists WP-02 only when the WP reads or edits another WP-02 file (`packaging/pins`, `packaging/pin.sh`, `tools/ghidra/headless.sh`, a check.sh step written for it).
