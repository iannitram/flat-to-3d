**Behaviour:**

`check.sh`:
- Uses `set -euo pipefail`, then `root=$(git rev-parse --show-toplevel)` and `cd "$root"`.
- If `CARGO_TARGET_DIR` is unset, it exports `$root/target` (gitignored). A value already set wins, so the §0 `export CARGO_TARGET_DIR=$SCRATCH/target` holds.
- `check.sh` is the only list of CI steps. Every step has a name and a group. Each step prints one result line:
  - `ok <step>`;
  - `skip <step>: <why> (fix: <hint>)` when a tool is missing on this machine;
  - `n/a <step>: <why>` when the files it checks have not landed yet;
  - `FAIL <step>: fix: <hint>`.
- It runs every selected step, even after a failure. It ends with `check.sh: <p> passed, <s> skipped, <n> n/a, <f> failed` and exits 1 if any step failed.
- Each step body is one `&&` chain. `set -e` is off inside a function called from `if`, so a step written as separate lines would hide a failure.
- Flags:
  - `--ci` turns every `skip` into a `FAIL`. `n/a` stays `n/a`.
  - `--only <group>` runs one group.
  - `--list` prints `<group> <step>` for every step, in order, and runs nothing.
  - `--tests '<args>'` makes step `test` run `cargo test --locked <args>` instead of `--workspace`.
  - An unknown flag exits 2 with the usage line.
- Group `rust`. If there is no root `Cargo.toml`, the whole group prints `n/a rust: no workspace yet`.
  1. `fmt`: `cargo fmt --all --check`. Fix: `cargo fmt --all`.
  2. `clippy`: `cargo clippy --locked --workspace --all-targets -- -D warnings`.
  3. `clippy-xr`: `cargo clippy --locked -p flat3d-viewer --all-targets --features xr -- -D warnings`.
  4. `clippy-capture`: the same with `--features xr,capture`, only if `pkg-config --exists libpipewire-0.3` succeeds. Otherwise `skip`, fix: `distrobox enter craft-build -- tools/check.sh`.
  5. `clippy-msvc`: `cargo clippy --locked -p flat3d-uevr-inject --target x86_64-pc-windows-msvc -- -D warnings`, if `rustup target list --installed | grep -qx x86_64-pc-windows-msvc`. Otherwise `skip`, fix: `rustup target add x86_64-pc-windows-msvc`. No SDK and no link are needed.
  6. `test`: `rt=$(mktemp -d) && trap 'rm -rf "$rt"' EXIT && XDG_RUNTIME_DIR="$rt" cargo test --locked --workspace`. The temp runtime dir means no fresh link snapshot exists (§1 A24).
  7. `lock`: `git diff --exit-code -- Cargo.lock`. Fix: `git checkout -- Cargo.lock`, because Cargo.lock is frozen after WP-01.
  8. `app-io`, if `crates/app/src` exists: fail when a `.rs` file under `crates/app/src`, other than `engine.rs`, matches `\bstd::(fs|process|net|thread)\b`, a `use std::{…}` group naming one of those, or `Command::new`. Fix: `return an Action; engine.rs does the I/O`. Today's `app/src` has none of these, so the step passes once WP-01 moves it to `crates/app/src`. `flat3d_inject::` imports are not checked.
- Group `py`:
  9. `py-compile`: `python3 -W error -m py_compile $(git ls-files '*.py')`.
  10. `unittest`: the bones §2 loop:
      ```sh
      for d in $(git ls-files '*test_*.py' | xargs -n1 dirname | sort -u | grep -vx 'decky/tests'); do python3 -m unittest discover -s "$d" -p 'test_*.py' || exit 1; done
      ```
      Inside check.sh the step runs in a function, so it uses `return 1` in place of `exit 1`; an `exit` would stop the run before the other steps and the summary.
      This covers `packaging/tests`, `tools/pm/tests`, `tools/session`, `tools/stereo`, `tools/docs`, `tools/re` and any later folder.

`tools/locked-test.sh <issue> <dest> <sha256>`:
- It replaces the awk/sha/CR/gh prose that WP-03, WP-04, WP-05 and WP-23 copy by hand.
- Exit codes are its own: 0 ok, 2 usage, 3 no snapshot, 4 check failed. Every failing exit prints one stderr line `locked-test: <token> fix: <hint>`.
- Steps:
  1. `SCRATCH` unset, or wrong arg count → exit 2, token `usage`, fix `export SCRATCH=<your scratch dir>`.
  2. The snapshot is `$SCRATCH/issues/<issue>.md`. If it is missing or empty, run the §0 issue snapshot command for that one issue (read-only `gh`). A `gh` failure → exit 3, token `no-snapshot`, fix `run the §0 issue snapshot step`.
  3. Extract into a temp file next to `<dest>`:
     ~~~sh
     awk '/^## Tests \(locked\)/{f=1} f&&/^```rust/{g=1;next} g&&/^```/{exit} g' "$snap"
     ~~~
  4. A CR byte → exit 4, token `cr`. A sha256 other than `<sha256>` → exit 4, token `sha-mismatch`. Both use fix `rm "$SCRATCH/issues/<issue>.md" and rerun`. On exit 4 the temp file is removed and `<dest>` is not written.
  5. Otherwise `mv` the temp file to `<dest>` and print `locked-test: ok <dest> <sha256>`. It never edits the body and never runs rustfmt.

`packaging/pins`:
- The file starts with a `#` header that describes the format and the TBD-at-pin rule (WP-13 points at it).
- Each line is `<key>.<field>: <value>`. Split at the first `.`, then at the first `: `. The value is everything after that `: `.
- A comment is a whole line starting with `#`. There are no inline comments. Blank lines are allowed.
- Fields:
  - `fetch: auto` keys need `version`, `url`, `size`, `sha256` (64 hex or `TBD-at-pin`) and `license`.
  - `fetch: manual` keys need `page` and `license`.
  - Optional fields: `md5`, `pinned`, `note`, `page`. Unknown fields are allowed.
  - `url: TBD-at-pin` and `size: TBD-at-pin` are allowed only while `sha256` is `TBD-at-pin`. A key with a TBD url must have `page`.
- `crate.<name>: <ver>` and `npm.<name>: <ver>` are version lists, not fetch keys. `pin.sh crate` exits 2, and `--all-tbd` skips them.
- `license`: from `gh api repos/<o>/<r> --jq .license.spdx_id`, or the vendor page.
- `sha256`: from the asset's `.digest` where GitHub gives one, else `TBD-at-pin`. Fill missing GitHub sizes and urls from the release metadata.

`pin.sh`:
- Exit codes are its own (tool exit codes stay per tool; there is no repo-wide table): 0 ok, 2 bad usage/pins/key, 3 cannot fetch (manual, TBD url, scheme, network, gh), 4 verify mismatch, 5 already pinned.
- Every exit prints one stable stderr line `pin: <token> retryable=<yes|no> fix: <hint>`. The tests assert the token.

| Exit | Token | retryable | Fix |
|---|---|---|---|
| 0 | `ok`, `dry-run`, `checked` | no | none |
| 2 | `usage`, `bad-pins`, `unknown-key`, `not-a-fetch-key` | no | name the bad line or key |
| 3 | `manual` | no | `download it from <key>.page (packaging/README.md)` |
| 3 | `url-tbd` | no | `set <key>.url from <key>.page, then rerun` |
| 3 | `scheme` | no | `use an https url` |
| 3 | `network`, `gh-failed` | yes | `rerun packaging/pin.sh <key>` (for gh: check `gh auth status` first) |
| 4 | `size-mismatch`, `md5-mismatch`, `sha-mismatch`, `digest-mismatch` | no | `do not pin; check <key>.url against <key>.page` |
| 5 | `already-pinned` | no | `packaging/pin.sh <key> --check` |

1. Parse the pins file. Exit 2 for a bad pins file, a bad key, a `crate`/`npm` key or bad usage.
2. A manual key exits 3 with the page URL. A TBD url exits 3 and names `<key>.page`.
3. A hex sha without `--check` exits 5.
4. Download:
   - `mkdir -p "${XDG_CACHE_HOME:-$HOME/.cache}/flat3d"`, then `tmp=$(mktemp -d "${XDG_CACHE_HOME:-$HOME/.cache}/flat3d/pin.XXXXXX")`, removed by a trap.
   - Command: `curl -fL --proto '=https' --proto-redir '=https' --tlsv1.2 --retry 3 --max-filesize <cap> -o "$tmp/f" <url>`. `<cap>` is `$((size+1))`, or `4294967296` when the size is TBD.
   - `--file <path>` skips the download and uses that file.
   - `PIN_ALLOW_FILE=1` changes the protocol flag to `--proto '=https,file'`. Without it, a `file://` URL exits 3 (`scheme`).
   - A curl failure exits 3 (`network`).
5. Verify:
   - size with `stat -c %s` (when the size is known);
   - md5 with `md5sum` (when the pin has `md5`);
   - sha256 with `sha256sum "$tmp/f" | cut -d' ' -f1`;
   - for a `https://github.com/<o>/<r>/releases/download/<tag>/<name>` URL, when `gh` is installed:
     ```sh
     gh api repos/<o>/<r>/releases/tags/<tag> --jq '.assets[]|select(.name=="<name>")|.digest'
     ```
     must equal `sha256:<hex>`. An empty or `null` digest skips this check. A `gh api` failure exits 3 (`gh-failed`). Without `gh`, the check is skipped.
   - With `--check` and a hex pin, a sha mismatch exits 4. With `--check` and a TBD pin, only size, md5 and gh-digest are verified.
   - Any mismatch exits 4 and leaves the pins file byte-identical.
6. Write:
   - `--check` exits 0 without writing.
   - `--dry-run` prints the new lines and writes nothing.
   - Otherwise rewrite only `<key>.sha256`, `<key>.size` (when it was TBD) and `<key>.pinned: <YYYY-MM-DD> tofu <checks>` (append or replace). `<checks>` lists only the checks that ran, joined with `+`: `size`, `md5`, `gh-digest`. Write via awk into a temp file in the pins file's dir, then `mv`.
7. Never extract, run or `git add` anything. Print `review: git diff --stat -- packaging/pins`.
- `--all-tbd` runs every auto key whose sha is `TBD-at-pin`, prints one token line per key, and exits with the highest code.

`issues_report.py` (issues):
- Input: `gh issue list --state open --limit 500 --json number,title,body,labels` (read-only), or `--json-file`. A `gh` failure exits 1 and prints gh's stderr.
- Labels arrive as objects: read them with `[l['name'] for l in labels]`.
- Scan every line that matches `[Bb]locked by:?\**\s*(.*)` (the rest of the line).
  - A line with `#(\d+)` refs counts only those refs.
  - A line with no `#` whose text does not start with `none` (any case) is external text, e.g. `Step 0 (SPEC M1) passing on 0.3.8`.
  - A `#n` that is not in the open set is treated as closed and dropped.
- Status: `blocked` if any ref is open; else `blocked-external` if there is any external text; else `ready`. An empty body is `ready`.
- `device`: true when the issue has the device label (default `needs-owner-device`).
- Markdown output: a table `# | title | status | blockers | device`. The device cell is `yes` or empty.
- `--json` output: a list of `{"number":int,"title":str,"status":"ready"|"blocked"|"blocked-external","blockers":[int],"external":[str],"device":bool}`. `blockers` holds only open refs.

`issues_report.py --roadmap` (plan lint and "what can start now"):
- Read-only. No network. It reads `--plan-dir` (default `docs/plans/roadmap-v2`): the index `03-wp-index.md`, each `WP-NN.md`, the §0 "Frozen after wave 1" list in `00-run-the-pass.md` and the §5 Q table and §7 OD table in `02-queues-and-decisions.md`.
- Index rows are `- WP-NN (wave W) <title> | closes … | files: … | depends: … | device: …`, split on ` | `. In `depends`, `-` means none and text in parentheses is ignored.
- Merged WPs come from `git log --merges --format=%s <base>` (default `origin/main`): a WP is merged when a subject contains its branch prefix `v2/wp-NN-` (§0 branch rule).
- It lists:
  - `ready`: not merged, and every dependency merged;
  - `blocked`: not merged, with the unmerged dependencies;
  - `owner-device`: merged WPs whose index row names a Q row;
  - `q-ready`: Q rows whose "Needs WPs" are all merged. In that column `NN` means WP-NN. A `Qn` entry is a session, which git cannot show, so it does not block the row; it is printed beside it as `after Qn`;
  - `ods`: the §7 OD rows with their current answer.
- Lint. Each finding prints `WP-NN: <rule>: <msg> (fix: <hint>)`, and any finding exits 1:
  - `wave-file-clash`: two WPs in one wave list the same file, or one's glob matches the other's path;
  - `depends-wave`: a WP depends on a WP in its own or a later wave;
  - `files-drift`: the index `files:` set differs from the paths in the WP's Files block. The block starts at the first line that begins `**Files` or `- **Files` (any suffix, e.g. `**Files (exclusive):**` or `**Files:**`) and ends at the next line that begins `**` (for a `- **Files` block, also `- **`). A path is a backticked token, outside parentheses and with no space, whose first segment is a top-level name some index row uses (`crates/`, `tools/`, `Cargo.toml`, …). Shorter forms such as `lib.rs` or `cli/setup.rs` are mentions. Brace forms (`a/{b,c}.rs`, nested too) expand, and a glob on either side matches. Every index path must be in the block. A block path missing from the index is drift unless another WP's row or a §0 frozen line lists it (then it is a mention). A block that says `as in the index` takes the index list;
  - `frozen-path`: a wave-2-or-later WP lists a §0 frozen path whose line does not name it;
  - `depends-drift`: the WP ids outside parentheses on the body's line that begins `**Depends on` differ from the index `depends`.
- `--json` prints `{"ready":[..],"blocked":[{"wp":..,"waiting_on":[..]}],"owner_device":[..],"q_ready":[..],"ods":[..],"lint":[{"wp":..,"rule":..,"msg":..,"fix":..}]}`.
- Globs: `**` and `*` match with `fnmatch`.

`issues_report.py --scope WP-NN` (check.sh step `scope`):
- Changed paths: `git diff --name-only $(git merge-base HEAD <base>)` plus `git ls-files --others --exclude-standard`.
- Each path must match WP-NN's index `files:`, or a §0 "Frozen after wave 1" line that names WP-NN (the body-only allowlist, e.g. `crates/engine/src/exec.rs` for WP-10).
- Each other path prints `scope: <path> is not in WP-NN's files (fix: move the change to the WP that owns it)`, and it exits 1.
