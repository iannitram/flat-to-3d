### WP-06: Logs view model + app Logs page
**Closes:** the logs gap (part of #121/#122; the `LogLines` DTO from code-map.md:149, which engine-b.md:70 found missing). WP-28 closes #121 and WP-33 closes #122, so this PR writes `Refs #121, #122`, not `Closes`.
**Files (exclusive):** `crates/engine/src/face/logs.rs` (WP-01 made the stub; `face.rs` has `pub mod logs;`), `crates/engine/tests/face_logs.rs`, `crates/app/src/logs_page.rs` (WP-01 made the stub), `crates/app/tests/logs_page.rs`.
**Frozen by WP-01 (§2 "Frozen signatures"; do not change them):**
- `read_logs(p:&EnginePaths, max:usize)->Vec<String>` does the I/O.
- `log_lines(text:&str, max:usize)->Vec<String>` is pure.
- `is_error_line(line:&str)->bool`.

WP-01 exports `face::logs::{log_lines, read_logs, is_error_line}` as stubs that return `Vec::new()`, `Vec::new()` and `false`. WP-06 writes the three bodies. Any helper it adds (`TAIL_BYTES`, `ERROR_WORDS`) is a private item inside `logs.rs`. The single log limit is `headset_view::DEFAULT_LOG_LINES` (500). There is no `LOG_LIMIT`, and `logs_page` has no limit constant of its own.

**Command contract: logs.** WP-28 and WP-33 cite this block and do not restate it.
- **Input:** `max`, the number of lines. The CLI form is `logs [--limit n]` (`ViewCommand::Logs{limit}`, WP-01). `n ≥ 1`; when `--limit` is absent it is `headset_view::DEFAULT_LOG_LINES` (500). The app always passes `DEFAULT_LOG_LINES`.
- **Engine call:** `face::logs::read_logs(p, max)`. Neither face reads a log file itself, and neither keeps its own `log_lines(text, limit)` or `read_log_text`.
- **Output:** `Vec<String>`, newest first, at most `max`. Missing files and dirs give `[]`, never an error. The CLI (WP-28) wraps it as `api::LogLines{text: headset_view::log_copy_text(&lines), lines}` for JSON.
- **Effects:** read-only. No writes, no spawn (no journalctl), no clock. The only reads are `p.link_log()`, `p.run_log()` and the run records under `state::runs_dir`.
- **App (WP-33):** `engine.rs` maps `LoadLogs` to `Logs(logs_page::Msg::Lines(read_logs(&p, DEFAULT_LOG_LINES)))`, with no CLI call. When it cannot build `EnginePaths`, it sends `Logs(logs_page::Msg::Failed(format!("{}: {}", e.code, e.message)))`, so the error code is kept. `Failed` keeps the old error path that `Loaded(Err)` covered. `Msg::Lines(Vec<String>)` is the name WP-33 matches on (`logs_page::Msg::Lines`); there is no `Loaded`.

**Paths.** `read_logs` takes every path from `EnginePaths` (§2 accessor table):
- `p.link_log()` is `log_dir/link.log` and `p.run_log()` is `log_dir/run.log`. `p.log_dir` is `$HOME/.local/state/flat3d` (writers: watch.rs:323 and flat3d-run.rs:34).
- `EnginePaths` has no `runs()` accessor. The run-record dir is `crate::state::runs_dir(&p.state_dir.to_string_lossy())`, which is `<state_dir>/runs` (state.rs:107-108). `p.state_dir` is the **runtime** dir `$XDG_RUNTIME_DIR/flat3d` or `/tmp/flat3d-<uid>` (state.rs:86-92).

Do not mix up `state_dir` (runtime) with `log_dir` (XDG state). The doc comment must say this. Line refs in this WP (watch.rs, wrapper.rs, flat3d-run.rs, state.rs, runs.rs, headset_view.rs) are as at main@2812f64, before WP-01 moved `inject/src` to `crates/engine/src`.

**Signatures (engine):**
```rust
//! The log lines both faces show. docs/code-map.md, API shape, LogLines.
use crate::paths::EnginePaths;
const TAIL_BYTES: u64 = 64 * 1024;
const ERROR_WORDS: [&str; 6] = ["error", "failed", "could not", "refused", "not found", "exec:"];
/// Pure: newest first, '\r' stripped, blank lines dropped, truncated to `max`. Kept lines are not trimmed.
/// Delegates to crate::face::headset_view::log_lines_newest_first (headset_view.rs:23-33;
/// its locked tests in crates/engine/tests/headset_view.rs:26-40 stay).
pub fn log_lines(text: &str, max: usize) -> Vec<String>;
/// I/O: link.log + run.log (log_dir, XDG state) + run records (state_dir/runs, runtime dir),
/// merged newest first, at most `max`.
pub fn read_logs(p: &EnginePaths, max: usize) -> Vec<String>;
pub fn is_error_line(line: &str) -> bool;   // lowercase contains any ERROR_WORDS
```

**Behaviour (`read_logs`):**
1. **Read each log file.** For each `(path, tag)` in `[(p.link_log(), "link"), (p.run_log(), "run")]`:
   - Open and read the file. If either fails (missing, is a dir, EACCES), skip it. On Linux, opening a dir succeeds and the read fails, so the read error must be handled too.
   - If len > `TAIL_BYTES`, seek to `len-TAIL_BYTES` and drop the first partial line.
   - Decode with `String::from_utf8_lossy`. Split it with the same rule as `log_lines` (split on `\n`, strip `\r`, drop blank lines), but keep file order for the ts step.
   - Each line's ts is its first space-separated token as `u64`. The writers use the formats `"{now} {line}"` (watch.rs:814) and `"{now} appid=.. pid=.. msg"` (wrapper.rs:170).
   - The ts rule: `match line.split_once(' ').and_then(|(t, r)| Some((t.parse::<u64>().ok()?, r))) { Some((ts, r)) => (ts, r), None => (prev_ts, line) }`. So a line whose ts doesn't parse inherits the previous line's ts in that file (0 at the start) and keeps the whole line as the rest.
   - Output `"{ts} {tag}: {rest}"`, with `ts` printed as the parsed `u64` (so `00999` prints `999`).
2. **Read the run records.** `read_dir(state::runs_dir(&p.state_dir.to_string_lossy()))` (skip on error), entries named `run-*.txt`:
   - Read the file. Parse it with `runs::parse_run_record` (runs.rs:38; header `flat3d-run 1`, tab-separated `appid/pid/mode`) and skip `None`.
   - ts = `metadata.modified()` as UNIX seconds (skip on error).
   - Output `"{ts} record: appid={a} pid={p} mode={3d|flat}"`.
3. **Merge.** Key = (ts desc, seq desc), where seq is the global read order (link, then run, then records). Truncate to `max` and return the `Vec<String>`. `read_logs` builds no `text`; callers that need it use `headset_view::log_copy_text` (headset_view.rs:35-37), which is `join("\n")`.

No journalctl, no clock, no writes.

**Signatures (app):**
```rust
//! The Logs page: state, messages, update. docs/code-map.md, Parts, crates/app/src.
use flat3d_inject::face::logs::is_error_line;
#[derive(Debug, Clone, Copy, PartialEq, Eq, Default)] pub enum Filter { #[default] All, Errors }
#[derive(Debug, Clone, Default, PartialEq, Eq)]
pub struct LogsState { pub lines: Vec<String>, pub filter: Filter, pub loading: bool, pub error: Option<String> }
#[derive(Debug, Clone, PartialEq)] pub enum Msg { Refresh, Lines(Vec<String>), Failed(String), SetFilter(Filter), CopyPressed }
#[derive(Debug, Clone, PartialEq, Eq)] pub enum Action { Load, Copy(String) }
pub fn update(state: &mut LogsState, msg: Msg) -> Option<Action>;
pub fn visible(state: &LogsState) -> Vec<&str>;   // Errors -> is_error_line
```
The page does no I/O. It returns an `Action`; WP-33's `engine.rs` does the read (see the command contract above).

`update`:
- `Refresh`: if loading, return `None`. Otherwise set `loading=true` and return `Some(Load)`.
- `Lines(v)`: set `lines=v`, `error=None`, `loading=false`, return `None`.
- `Failed(e)`: keep the lines, set `error=Some(e)`, `loading=false`, return `None`.
- `SetFilter(f)`: store it, return `None`.
- `CopyPressed`: if `visible` is empty, return `None`. Otherwise return `Some(Copy(visible.join("\n")))`. WP-33 turns that into `iced::clipboard::write` (iced-packaging.md:20).
