- **Behaviour (`run_with`, one arm per `LinkCommand`):**
  - **Watch:** `(io.watch)(ctx.paths)`. If it returns (tests only), `Ok(Value::Null)`.
  - **Snapshot:** `read_snapshot(p)`. `Ok(Some(s))` → `s.effective(io.now)`; `Ok(None)` → `LinkSnapshot::stopped(io.now)`; `Err(e)` → `io`. Returns the full `LinkSnapshot` as JSON.
  - **SwitchGet{appid}:** `read_settings(&p.settings())` (Err → `io`) → `SwitchState{appid, on:game_on(appid)}`. A missing file is not created.
  - **SwitchSet{appid,on}:** read, `set_game`, `write_settings` (Err → `io`) → `SwitchState{appid,on}`.
  - **SettingGet/SettingSet{key,..}:** `Auto3d` ↔ `settings.auto_3d`, `Tunnel` ↔ `settings.tunnel`. Set writes the file. Returns `SettingState{key:key.as_str().into(), on}`.
  - **Install:** `install::execute(&install_plan(&home, &src_dir), ctx.runner)`, with `home = p.home.to_string_lossy()` and `src_dir = io.src_dir.to_string_lossy()`. **Uninstall:** `install::execute_uninstall(&uninstall_plan(&home), ctx.runner)`. Both return `InstallReport`. WP-20's errors pass through unchanged.
  - **Run{appid,argv}:**
    - `env = io.env.clone()`. Insert `SteamAppId=<appid>` when neither `SteamAppId` nor `SteamGameId` is set (wrapper.rs:98-100), and remember that it was added.
    - Call `wrapper::run_with(&argv, &env, p, io.pid, io.now, ctx.runner, |l| (io.exec)(l))`. `argv` is passed verbatim, including any `--json` (`parse_any` strips `--json` only before the first `--`).
    - A launcher `Err(e)` → `ApiError::new("command-failed", &e.to_string())`, which exits 1. `Ok(())` (tests only) → `json!({"message": launch.message})`.
    - `exec_launch`: `Command::new(argv[0]).args(&argv[1..])`, `.envs(spec.env)`, `env_remove` for each `spec.unset`, and `.env("SteamAppId", appid)` when it was added. It spawns `spec.sidecar` (if any) with `--until-pid <pid>` appended, the same rule WP-01/WP-31 give `flat3d-run.rs`. Then `CommandExt::exec`, which returns only on error. This `Command::new` is allowed: WP-01's `tests/architecture.rs` allowlist has a permanent `cli/link.rs` (WP-08) entry, because the exec replaces the process. No other spawn goes in this file; use `ctx.runner`.
  - **request_3d (A24 one-actor rule):** it only writes a request. `read_snapshot(p)`:
    - `Ok(None)` or `Err(_)` → `Err(ApiError::new("link-not-ready", "Link service is not running. Start it: systemctl --user start flat3d-link.service (first time: flat3d-inject install)."))`.
    - `Ok(Some(s))` with `state::is_stale(s.updated, now)` (>10 s, state.rs:143) → `Err(ApiError::new("link-not-ready", "Link service stopped updating (last update <now - s.updated> s ago). Restart it: systemctl --user restart flat3d-link.service."))`.
    - In both cases nothing is written and nothing is spawned (the fn has no runner).
    - Fresh → `write_request(p, r)` (Err → `io`) → `Ok(LinkReport{state:s.state, message:format!("Requested {}.", request_text(r))})`, i.e. `"Requested start-3d."` or `"Requested stop-3d."`.
  - **Error codes:** closed at the 8 in `ERROR_CODES` (api.rs:77-86) for this pass (ruling D6): usage, not-built, not-found, bad-recipe, refused, link-not-ready, command-failed, io. This WP uses `io`, `command-failed` and `link-not-ready`, plus whatever `install::*` returns. A new failure maps to an existing code with a specific message. No WP adds a code.
  - **Exit codes:** WP-01's `render` maps them (cli.rs:95-96): `usage` and `not-built` exit 2, every other error exits 1. This WP does not use the dispatch exit hook (ruling D2).
  - **CLI surface:** `cli::USAGE`, `cli::parse` and `cli::parse_any` are WP-01's and stay unchanged. Link usage errors keep the locked `parse_link` text (`usage: flat3d-inject <form>`, cli_link.rs:64-66). There is no separate `LINK_USAGE` const.
- **Effects (as declared in WP-01's `cli::COMMANDS` rows, WP-01.md:460-474, ruling D2; `SideEffect` values in brackets):**
  - `snapshot`, `switch get`, `setting get` [`ReadOnly`]: no runner call, no file written.
  - `switch set`, `setting set` [`WritesFiles`]: write `p.settings()` only.
  - `install`, `uninstall` [`WritesFiles, RunsCommands`]: write or remove files under HOME (WP-20's rules) and run `systemctl --user`.
  - `run` [`WritesFiles, RunsCommands`]: writes the run record, then execs the game (and its sidecar).
  - `watch` [`WritesFiles, RunsCommands`]: runs the link service loop and never returns.
  - `start-3d`, `stop-3d` [`WritesFiles`]: write the request file, and only when the snapshot is fresh.
