### WP-09: Watch service correctness (3D half)
> Rewritten 2026-11-10 (ruling 42). The tether half of this WP (non-fatal tether failure with retry, executing the heal actions, `Tether::{set_wivrn,set_sleep,sync_wifi}`, the snapshot heartbeat for the tun0 wait) is dropped: Flat to 3D no longer has a tether (WP-36 removes the tether code, WP-10's included). What stays is the 3D link: the allow-debugging event, the production WiVRn start args and Stop 3D through `link::stop_3d`.
- **Wave:** 4. It builds on the service after WP-36 has removed the tether from it (wave 2b), and on WP-11's and WP-12's bodies (wave 2).
- **Closes:**
  - the allow-debugging event
  - production WiVRn start args
  - Stop 3D in the service through `link::stop_3d`, so a second stop is not an error
- **Files (exclusive):**
  - `crates/engine/src/watch/machine.rs`
  - `crates/engine/src/watch/service.rs`
  - `crates/engine/tests/watch_service.rs`
  - The frozen `watch` facade is not touched. Test files use crates/ paths only, never inject/ ones.
  - Find each item by its name, not by an old line number: the code is in `watch/service.rs` (the `Service`, its inline tests and `Fake`) or `watch/machine.rs` (`link_commands`, `note_event`, `note_text`).
- **Uses (frozen by WP-01 §2, bodies from WP-11/12/35/36; call exactly these shapes):**
  - `crate::wivrn::{WivrnStart{scope:Option<FlatpakScope>,app:String,flags:Vec<String>}, SERVER_FLAGS:[&str;2], QUEST_APPS, QuestApp{package:String,version:Option<String>}, detect_quest_app(r:&mut dyn exec::CommandRunner, serial:&str)->Option<QuestApp>}`. `QuestApp` has no tuple form.
  - `crate::link::{start_3d_commands_with(&WivrnStart)->Vec<Vec<String>>, stop_3d(&mut dyn CommandRunner)->Result<LinkState,LinkError>, WIVRN_APP}`.
  - `crate::link::adb::{AdbChoice, AdbRunner::new(inner, adb:&str, serial:Option<&str>)}` (WP-35 moved them out of `tether/adb.rs`). After WP-36 the service has one runner shape (`exec::CommandRunner`), so no adapter between a "relay shape" and a "link shape" is needed.
  - `HealthLoop::tick` after WP-36 (battery and temperature only; no `mode`, no `heal`, no `tunnel`). WP-09 does not call `tick` itself; `publish()` does.
  - `machine::note_event(n:Note)->EventKind` stays the frozen free `pub fn` (§2). WP-09 adds no method with that name.
- **Signatures (all inside WP-09's own files):**
  - machine.rs: `pub(crate) fn link_commands_with(effect:&Effect, w:&crate::wivrn::WivrnStart) -> Vec<Vec<String>>`. StartLink gives `start_3d_commands_with(w)`, Reattach gives `start_3d_commands_with(w)[2..]`, and every other effect gives the same result as `link_commands`. The locked `link_commands` stays byte-identical. It is not re-exported.
  - service.rs: a private field `quest_app:Option<(String,String)>` (serial, package), so the dumpsys probes run once per headset.
- **Behaviour:**
  - **Unauthorised:** in the `Seen::Unauthorised` arm, when `self.unauthorised` was false (the move into the state), push `ring.push(note_event(Note::AllowUsbDebugging), note_text(Note::AllowUsbDebugging))`. That gives kind `allow-debugging` and the text "Put the headset on and allow USB debugging.". The push comes before `self.unauthorised = true`. There is no repeat while the device stays unauthorised.
  - **Health probe runner.** `publish()` must run the health loop's `adb …` word lists through the adb in use, so the probes run as `<adb> -s <serial> …` and not as bare `adb`. WP-09 passes `publish()` a `link::adb::AdbRunner` over the service's shared runner, built as in `adb_run`. Nothing else in `publish()` changes.
  - **Stop 3D:** `Effect::StopLink` runs `link::stop_3d(&mut AdbRunner::new(Shared(Rc::clone(&self.runner)), &self.adb.path, Some(&self.serial)))` in place of `run_steps(link_commands(&effect))`. `Ok(_)` logs nothing. `Err(e)` logs `stop: {e.message}`. WP-12's `stop_3d` returns `Ok(Stopped)` when the server unit is already gone, so a second stop logs no error. `roll_back` keeps its `stop_3d_commands` best-effort run.
  - **WiVRn start:**
    - Before `StartLink`/`Reattach`, build `w = WivrnStart{scope:None, app, flags:SERVER_FLAGS.map(String::from).to_vec()}` (the same as `WivrnStart::default()` with `app` set).
    - `app` is `detect_quest_app(&mut AdbRunner::new(Shared(Rc::clone(&self.runner)), &self.adb.path, Some(&self.serial)), &self.serial).map(|q| q.package).unwrap_or_else(|| link::WIVRN_APP.to_string())`. It is cached in `quest_app` per serial, so the 5 dumpsys probes run once per headset.
    - StartLink/Reattach run `run_steps(now, &link_commands_with(&effect,&w), true)`.
  - Grace still maps to `Ready` in `state_text` (OD4).
