- **Behaviour:**
  - **Tether failure:**
    - In `execute`, `Err(message)` from `StartTether` keeps today's `log(now,"tether: {message}")`. It also pushes `ring.push(EventKind::TetherError, &message)` and sets `tether_failed=true`.
    - The link start in the same batch still runs (`wivrn_by_tether` stays false).
    - Retry: in `tick`, on a feed frame that `classify` reads as `Ready` while `self.ready` is already true, retry only when `settings.tunnel` is on, the tether mode is Off (or there is no tether), `tether_failed` is set and `now >= retry_at`. The retry calls `connect_tether(false)` once. Ok clears the flag. Err logs, pushes nothing, and sets `retry_at = now + MIN_HEAL_GAP_SECS` (30).
    - The error prefixes "Tether command failed" / "Could not run tether command" are kept.
  - **Unauthorised:** in the `Seen::Unauthorised` arm, when `self.unauthorised` was false (the move into the state), push `ring.push(note_event(Note::AllowUsbDebugging), note_text(Note::AllowUsbDebugging))`. That gives kind `allow-debugging` and the text "Put the headset on and allow USB debugging.". The push comes before `self.unauthorised = true`. There is no repeat while the device stays unauthorised.
  - **Health probe runner.** WP-01's `publish()` passes the raw `&mut Shared(Rc::clone(&self.runner))` to `HealthLoop::tick`, so the loop's `adb …` word lists run as bare `adb`. WP-09 changes that one argument to a private adapter in service.rs: `struct ViaAdb<R>(TetherAdb<Shared<R>>)`, built as `ViaAdb(TetherAdb::new(self.adb.clone(), &self.serial, Shared(Rc::clone(&self.runner))))` (the same build as `adb_run`). It implements `exec::RelayRunner`: `run(c)` is `self.0.run(c)`, `start_relay(c, _)` is `self.0.start_relay(c)` and `stop_relay()` is `self.0.stop_relay()`. The probes then run as `<adb> -s <serial> …`, and a non-adb word list (`ps`) passes through unchanged. Nothing else in `publish()` changes.
  - **Heal.** At the end of `tick`, after `publish`, take the `heal` that `publish()` stored. If it is Some, call `self.heal(now, h)`. If `gave_up` is set, `heal` returns at once.
    - `RestartClient`: `run_steps(now, &[client_stop_command()], false)`, then `run_steps(now, &client_start_commands(), false)`. Both go through `adb_run`/`TetherAdb`, which gives `<adb> -s <serial> …`.
    - `RestartAdbThenClient`: `self.runner.borrow_mut().run(&[adb.path,"kill-server"])`, then `[adb.path,"start-server"]`, run directly. `TetherAdb::run` always inserts `-s` (adb.rs:148-158), and only the link-shape `AdbRunner` exempts server commands (adb.rs:198-201). Then the `RestartClient` sequence.
    - `FullReconnect`: if there is a tether, call `tether.disconnect()` (Err is logged), then `connect_tether(false)`, which is `connect_tunnel_only(foreign)` with `foreign` from `stepaside::foreign_relay` (watch.rs:693 today). With no tether it only logs.
    - `GiveUp`: one `ring.push(EventKind::TetherError, "The USB tunnel kept dropping. Unplug the headset and plug it back in.")`, then `gave_up=true`. `gave_up` is cleared when `connect_tether` next returns Ok.
    - `None`: nothing.
    - Every failure is logged. No panic, no `unwrap` on runner output. The healer's next tick decides the next step.
  - **Stop 3D:** `Effect::StopLink` runs `link::stop_3d(&mut AdbRunner::new(AsLink(Shared(Rc::clone(&self.runner))), &self.adb.path, Some(&self.serial)))` in place of `run_steps(link_commands(&effect))`. `Ok(_)` logs nothing. `Err(e)` logs `stop: {e.message}`. WP-12's `stop_3d` returns `Ok(Stopped)` when the server unit is already gone, so a second stop logs no error. `roll_back` keeps its `stop_3d_commands` best-effort run.
  - **WiVRn start:**
    - Before `StartLink`/`Reattach` and before `connect_tether(true)`, build `w = WivrnStart{scope:None, app, flags:SERVER_FLAGS.map(String::from).to_vec()}` (the same as `WivrnStart::default()` with `app` set).
    - `app` is `detect_quest_app(&mut AdbRunner::new(AsLink(Shared(Rc::clone(&self.runner))), &self.adb.path, Some(&self.serial)), &self.serial).map(|q| q.package).unwrap_or_else(|| link::WIVRN_APP.to_string())`. It is cached in `quest_app` per serial, so the 5 dumpsys probes run once per headset.
    - StartLink/Reattach run `run_steps(now, &link_commands_with(&effect,&w), true)`.
    - `connect_tether` calls `tether.set_wivrn(w.app.clone(), w.flags.clone())` before `connect`/`connect_tunnel_only`.
    - After an Own connect, call `tether.sync_wifi()` once and log `wifi: {decision:?}`. `SyncDecision` is a fieldless enum (wifi.rs:163-170), so no SSID or PSK reaches the log. Any command line is logged only through `wifi::redact_command`.
  - **Heartbeat:**
    - `Service::new` installs the default raw sleeper `|ms| thread::sleep(Duration::from_millis(ms))`, so production gets the heartbeat with no change to `watch/run.rs`.
    - `tether_for`, when it creates a `Tether`, calls `set_sleep` with a closure that captures `Rc` clones of `sleep`, `last` and `slept_ms`, plus `paths.snapshot()`. Each call runs the raw sleeper and adds `ms` to `slept_ms`. If `last` is Some, it writes it with `updated = last.updated + slept_ms/1000` through `write_snapshot` (errors ignored).
    - `publish` stores its snapshot in `last` and resets `slept_ms` to 0.
    - This keeps `WaitTun0` (up to 15×1.5 s, then 8×1.5 s) from making the snapshot stale (10 s).
  - Grace still maps to `Ready` in `state_text` (OD4).
