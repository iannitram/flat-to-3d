- **Behaviour:**
  - **`run_plan_in`** runs the steps in order. It appends every argv it passes to `r.run` to `out.ran`, before any adb rewrite. A tun0 probe is one `r.run(tun0)`: present means `Ok(o)` with `relay::tun0_present(&o)`, and an `Err` counts as absent. Per `TetherStep` (plan.rs:8):
    - `Run(c)`: `r.run(c)?`.
    - `SleepMs(ms)`: `sleep(ms)`.
    - `IfVpnUp(c)`: one probe; runs `c` (`?`) only when present.
    - `IfNoTun0(cs)`: one probe; runs each of `cs` (`?`) only when absent.
    - `WaitTun0{tries,every_ms}`: up to `tries` probes, with `sleep(every_ms)` between two probes (not after the last, not after a hit). It sets `out.tun0` and never errors.
    - `WaitWifi{tries,every_ms}`: the same loop with `wifi::quest_ssid_command()` until `wifi::parse_quest_ssid` is `Some`. It never errors.
    - `KillStaleRelay`: does nothing when `ctx.relay` is empty. Else `r.run(ps)?` and `stepaside::parse_ps`; for each `(pid, args)` whose first whitespace word equals `ctx.relay[0]`, `r.run(["kill", pid])`, ignoring its error.
    - `SpawnRelay`: an empty `ctx.relay` gives `Err("No relay command")`. Else `r.start_relay(&ctx.relay, "")?`. The runner supplies the adb path; inside `Tether` the adapter below does.
    - `CheckRelayAlive`: an empty `ctx.relay` gives `Err("No relay command")`. Else `r.run(ps)?`; if no `parse_ps` entry has `args == ctx.relay.join(" ")`, it returns `Err("Tether relay exited during startup")`.
    - `KillRelay`: `r.stop_relay()?`.
  - **`run_plan`** is `run_plan_in(steps, &PlanCtx::default(), r, sleep, &mut PlanRun::default())`.
  - **Inside `Tether`** the plan runs through a private adapter in `tether.rs`: `struct Via<'a,R>{ adb:&'a mut TetherAdb<R>, spawned:bool }`, with `impl<R: adb::CommandRunner> RelayRunner for Via<'_,R>`.
    - `run` calls `TetherAdb::run`, so `adb` becomes `<path> -s <serial>`.
    - `start_relay(c,_)` calls `TetherAdb::start_relay(c)`, which supplies the real adb path, and sets `spawned = true` on Ok.
    - `stop_relay` calls `TetherAdb::stop_relay`.
    - The ctx is `PlanCtx{relay: relay::relay_command(&relay::relay_path(&home), &serial)}`. `&mut *self.sleep` and `&mut self.adb` are disjoint field borrows.
  - **`connect` / `connect_tunnel_only`** keep their signatures, the "already active" and "No adb" checks, and the reverse bookkeeping in `run_connect_command`. The "No adb is available: …" message in `tether.rs` gains the ending `; fix: flat3d-inject install` (`questions.md` entry 25; no test pins that text). The shorter message in `tether/adb.rs` is not touched. Steps:
    1. `reverse --list` (as today);
    2. the WiVRn lists: the stored `set_wivrn` lists, else `link::start_3d_commands()`. `connect_tunnel_only` keeps only the first list (`adb devices`), as today. Each goes through `run_connect_command`;
    3. Own only (`!foreign_relay`): `run_connect_command(client_start_commands()[0])` (reverse localabstract);
    4. Own only: `adb shell pm list packages com.genymobile.gnirehtet` (`?`), then `install -r <relay::apk_path(home)>` (`?`) only if no output line trims to `package:com.genymobile.gnirehtet`. `connect_tunnel_only` runs this too, as it installs today;
    5. Own only: `run_plan_in(&connect_plan(), ctx, Via, sleep, &mut out)`. The client `am start` now runs only through `IfNoTun0`. After the call (Ok or Err), `client_started` is true when `out.ran` contains `client_start_commands()[1]`.
    - Connect never calls `sync_wifi`. The caller (WP-09) calls it after an Own connect.
  - **One APK path.** `relay::apk_path(home)` = `<home>/.local/share/flat3d/bin/gnirehtet.apk` is the only path connect installs from. It is the `tools_dir` copy that WP-20's install makes.
  - **Connect rollback** (on any Err), in this order:
    1. when `client_started`: client stop, and force-stop if that fails;
    2. when `Via.spawned`: `adb.stop_relay()`, ignoring its error;
    3. `cleanup_reverses()`, appending its error as today.
    - The mode stays Off.
  - **`disconnect`, Own mode:** `run_plan_in(&disconnect_plan(), …)` through `Via`.
    - On Ok: reset like `drop_local`, but without a second `stop_relay` (mode Off, `client_started=false`, `added_reverses` cleared).
    - On Err: if `out.ran` lacks `relay::remove_reverse_command()`, run `adb.stop_relay()` and that remove, ignoring their errors. Return the first error and leave the mode Own (as today).
    - The Off and QuestTether branches are unchanged.
  - **`sync_wifi`** is best effort: it never returns Err and never touches the mode.
    1. `pc = run(active_ssid_command()).ok().and_then(parse_active_ssid)`; `quest = run(quest_ssid_command()).ok().and_then(parse_quest_ssid)`;
    2. `d = sync_decision(pc, quest, self.wifi_attempts)`;
    3. only on `Switch`: `run(credentials_command(pc))` → `parse_credentials`; `None` or an Err counts as a failed attempt. Else `argv = wifi::connect_argv(ssid, sec, psk)` and `joined = run(&argv).is_ok()`. Then `wifi_attempts = next_attempts(prev, joined)`;
    4. store `d` for `last_wifi` and return it.
    - The PSK never appears in a stored string or an error. `Tether` keeps no command text; a caller that logs the attempt logs the `SyncDecision` (a fieldless enum, wifi.rs:164-170) or a `redact_command` line, never the argv.
  - **`ProcessRunner::run` errors** (exec.rs, body only). The prefixes stay, for watch/service.rs and its tests (watch.rs:915,922):
    - non-zero exit: `Tether command failed: exit <code>` (or `exit signal <N>`, via `std::os::unix::process::ExitStatusExt::signal`), then `; <the last 4 non-empty stderr lines, trimmed, joined " / ">` when stderr has any. With no stderr it is the bare `Tether command failed: exit 1`;
    - spawn failure: `Could not run tether command: <io error>`;
    - the `start_relay` and `stop_relay` messages are unchanged.
  - **Caller note:** a fresh connect can sleep about 34 s in `WaitTun0`, longer than the 10 s snapshot staleness. WP-09 injects a heartbeat sleeper through `set_sleep`.
