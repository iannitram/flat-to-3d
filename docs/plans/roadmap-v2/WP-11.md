**Behaviour of `tick`**

1. **Tunnel probe.** It runs only when `mode == TetherMode::Own`, and then only when `last_tun0` is None or `now - last >= 5`. In `Off` or `QuestTether`, nothing runs for the tunnel and the healer is not fed. The result then has `tunnel: false`, `heal: None` and `stats: None`, and `up_since` is cleared.
   - `ps -eo pid=,args=` gives `relay_alive = foreign_relay(&parse_ps(out), None)`. A runner `Err` counts as false.
   - `adb shell ip addr show tun0` gives `tun0 = Ok && tun0_present(out)` (`relay.rs:73-78`).
   - `adb shell cat /proc/net/dev` gives `counters`: `parse_tun0_bytes(out)` when `tun0` is true and the command is `Ok`, else `None`. Then `(rx, tx) = meter.sample(now*1000, counters)`. From here on, `rx` and `tx` are these rates in bytes per second, not the raw counters.
   - `tunnel = tunnel_state(relay_alive, tun0) == Connected`. `up_since` is set on the first Connected and cleared on anything else.
   - `h = healer.observe(now, relay_alive, tun0)`:
     - `Heal::None` gives `heal: None`.
     - `GiveUp` gives `Some(GiveUp)` once (latched by `gave_up`), then None.
     - Anything else gives `Some(h)`.
   - While `tunnel` is up, `soak.sample(rx+tx)`.
   - It appends the soak line `sample\t{now}\t{rx}\t{tx}\t{tun0 0|1}\t{relay 0|1}\t{h.word()}\n`.
2. **Health poll.** It runs in every mode (SPEC M10: with Auto 3D off, plugging in still brings up health), when `last_health` is None or `now - last >= 30`.
   - It runs `r.run(&health_command())` (`adb shell dumpsys battery`). `Ok` gives `Some(parse_dumpsys_battery)`. `Err` gives `None`.
   - With `Some(health)`, `gate.observe(health.zone, playing)` may give a kind, and then `HealthTick.toast = Some((kind, toast_text(kind, temp)))`. A failed poll (`None`) does not call the gate. `toast` is None on every other tick.
   - It appends `health\t{now}\t{battery|-}\t{temp|-}\t{zone:?}\n` (zone lower-cased). A failed poll writes `-`, `-` and `unknown`.
   - Between polls, the cached health is returned.
3. **Stats.** `stats = tunnel.then(|| Stats{rx_bytes_s, tx_bytes_s, uptime_s: now-up_since, reconnects: healer.reconnects()})`.
4. **Soak file.** Writes are best-effort: `create_dir_all` on the parent, then append. The loop is the only writer of `soak_file`. `finish` appends `SoakSummary::to_text()` (locked format, starting `flat3d-soak 1`). A reader takes the block after the last `flat3d-soak 1` line.
   - The `Heal::word()` values and the field order of the `sample` and `health` lines are a file format. They are never renamed or reordered. `heal_words_and_soak_fields_are_locked` pins them.
5. **Word convention.**
   - The `ps -eo pid=,args=` probe runs on the host, as `connect_tether` does today (`watch.rs:691`). Its word list starts with `ps`, not `adb`.
   - The `ip`, `/proc/net/dev` and `dumpsys` word lists start with the literal `adb`, the same as `health_command()`.
   - The caller passes a runner that resolves `adb` to the path plus `-s <serial>` and passes any other word list through unchanged. `TetherAdb::run` does exactly this (`tether/adb.rs:148-157`).
6. **Effects.** `tick` runs only the four read-only probes above (`ps`, `ip addr show tun0`, `cat /proc/net/dev`, `dumpsys battery`) and appends to `soak_file`. It never runs a heal, never calls `start_relay` or `stop_relay`, and writes no other file. `tick_never_runs_a_heal` checks this.
7. **Contract for the callers** (not code here):
   - WP-01's `publish()` calls `tick(sys::unix_now(), mode, playing, r)` with the current `TetherMode` and the game-running flag. The loop gates the tunnel itself. `publish()` pushes `tick.toast` into the event ring when it is Some, `current()` takes health, stats and tunnel from the `&HealthTick`, and `publish()` keeps `tick.heal` for WP-09. `Service` builds `HealthLoop::new(sys::unix_now(), 0, None)`.
   - WP-09 executes the kept heal:
     - `RestartClient` → `relay::client_stop_command()`, then `relay::client_start_commands()`;
     - `RestartAdbThenClient` → adb `kill-server`/`start-server`, then the client, as above;
     - `FullReconnect` → `Tether::disconnect` + `connect_tunnel_only`;
     - `GiveUp` → push `EventKind::TetherError`.
   - `TetherAdb` (`adb.rs:128-168`) has inherent `run`/`start_relay`/`stop_relay` but does not implement `RelayRunner`. The runner passed to `tick` must be a small `RelayRunner` adapter over it in `service.rs`, like today's `adb_run` (`watch.rs:660-667`). WP-09 owns `service.rs`.

**Tests**

Locked, unchanged: `tests/tether_heal.rs` (8 tests), `health_toast.rs`, `health_parse.rs`, `stats_soak.rs`, `stats_rate.rs`.

New `crates/engine/tests/tether_health.rs` uses a local `Fake` that implements `flat3d_inject::exec::RelayRunner`.
- Its replies are keyed by `argv.join(" ")`. Each key holds a list of replies: a call takes the front one, and the last one repeats once it is the only one left.
- An argv with no key gets `Err("no reply")`.
- It records every argv in `ran`. `start_relay` records `["relay", argv.., name]` and `stop_relay` records `["relay", "stop"]`, as `testing::FakeRunner` does.
- It is keyed, not FIFO, so the order of commands inside a tick doesn't matter.

Every call is `tick(t, TetherMode::Own, playing, &mut fake)` unless a case says otherwise. Cases:
- `a_good_tunnel_fills_health_stats_and_tunnel`:

  - Ticks at t=0 and t=5.
  - Expected: `tunnel` is true, `heal` is None, `toast` is None and `health.zone` is Green. The second probe gives `stats.rx_bytes_s == 1000` and `stats.tx_bytes_s == 1000`.
- `three_misses_then_one_reconnect`: ip returns `Device "tun0" does not exist.`. Ticks at t=0,5,10 give heals `[None, None, Some(RestartClient)]`. Exactly one is non-None.
- `ticks_between_probes_run_nothing`: t=0, then t=1..4. `ran` doesn't grow for the tun0 words.
- `battery_is_polled_every_30_s`: the count of `dumpsys battery` over t=0..=60 step 5 is 3.
- `other_modes_skip_the_tunnel_probe`: `TetherMode::Off` and `QuestTether` give no `ip addr`, `ps` or `/proc/net/dev` in `ran`, `tunnel` false and `heal` None, but `dumpsys battery` still runs.

**Inline facts**
- Zones (`health.rs:97-104`): Green < 38.0, Yellow 38.0..=42.0, Red > 42.0. Temperature is in tenths (`/10.0`).
- `EventKind::{Warm, Hot}` texts: `health.rs:42-48`. The gate is locked in `tests/health_toast.rs:7-30` ("nothing toasts while not playing").
- Soak path: `stats::soak_path(home, start)` = `{home}/.local/state/flat3d/soak-{start}.txt`.
- Heal constants: `MISS_LIMIT=3`, `MIN_HEAL_GAP_SECS=30`, `FLAP_WINDOW_SECS=600`, `FLAP_MAX=6`, `MAX_RECONNECTS=10`.
- The ladder cycles RestartClient → RestartAdbThenClient → FullReconnect.
- The watch loop ticks at 1 s (`watch.rs:890`).
- Relay detection: an argv word is `run` or `relay`, the command contains `gnirehtet`, and the executable is not adb (`stepaside.rs:20-33`).
- `/proc/net/dev`: rx is the first number after `tun0:` and tx the ninth. A line with any non-numeric field parses as None (`relay.rs:86-99`).
