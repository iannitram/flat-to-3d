**Behaviour**
- **`parse_pins`.**
  - It skips blank lines and lines starting with `#`, and strips a ` #…` comment from the end of a value.
  - It splits `<key>.<field>: <value>` at the first `.` and the first `: `.
  - It skips the keys `crate` and `npm`, which are version lists only.
  - It ignores unknown fields, such as `pinned`. If a field repeats, the last one wins.
  - `size` parses as `u64`. An absent or unparsable size is `0`.
  - `fetch: auto` → `Some(Auto)`, `fetch: manual` → `Some(Manual)`, anything else or absent → `None`.
- **`pin_in`.** The checks run in this order, and the first that fails is the error.
  - A missing key → `UnknownKey`.
  - `fetch: manual` → `Manual`. A `fetch` of `None` counts as `Auto`.
  - A sha256 of `TBD-at-pin` → `TbdAtPin`, with the message "`<key>` has no recorded sha256; run packaging/pin.sh `<key>`".
  - A missing url → `BadPin{field:"url"}`. A size of `0` → `BadPin{field:"size"}`. A sha256 that isn't 64 hex characters → `BadPin{field:"sha256"}`.
- **`is_fetched`.** Returns true when `cache_dir/.flat3d-fetch` equals the pin's sha256 (lowercase) plus `\n`. It reads that one file, runs no command and writes nothing. WP-27 (`ensure_applied`, `setup fetch`) and WP-29 (doctor) call it. They never rebuild the cache path or read the marker themselves.
- **`fetch` / `fetch_with`.**
  1. Check the pin the same way as `pin_in`. Then check the scheme: `https://` only, plus `file://` when `allow_file` is set. Anything else → `Scheme`, and no command runs.
  2. `dir = cache_dir`. If `is_fetched`, return `Ok(dir)` and run no commands (idempotent). An existing dir whose marker is missing or different is removed with `remove_dir_all`.
  3. `tmp = p.cache()/<key>/.<version>.tmp`: remove it (ignore `NotFound`), then `create_dir_all(<tmp>/out)`. `bsdtar -C` needs the dir to exist. `name` = the last URL segment, cut before `?`.
  4. Run `curl --proto =https --proto-redir =https --tlsv1.2 -fL --retry 3 --max-filesize <size+1> -o <tmp>/<name> <url>`. With `allow_file`, both `--proto` and `--proto-redir` are `=https,file`. A failure → `Command{command: argv joined, message: stderr trimmed}`.
  5. Check the size with `fs::metadata` → `SizeMismatch`.
  6. Run `sha256sum <tmp>/<name>` and take the first token. A failing `sha256sum` → `Command`. Compare both sides as lowercase hex → `ShaMismatch`.
  7. If `name` ends in `.zip`, `.7z`, `.tar`, `.tar.xz`, `.txz`, `.tar.gz`, `.tgz` or `.tar.zst`, run `bsdtar -xf <tmp>/<name> -C <tmp>/out`. This keeps the archive's top folder. Otherwise `fs::rename` the file to `<tmp>/out/<name>` (apk, AppImage, runtime).
  8. Write `<tmp>/out/.flat3d-fetch` (the lowercase sha256 plus `\n`), then `fs::rename(<tmp>/out, dir)` (atomic), then remove `tmp`.
  9. On any error, remove `tmp`. `dir` is never half-made.
- **Messages.** Each refusal with one fix names it:
  - `TbdAtPin`: "run packaging/pin.sh `<key>`" (above).
  - `SizeMismatch` and `ShaMismatch` name the key, the expected and the got values, and end "run packaging/pin.sh `<key>` --check". The plain `pin.sh <key>` exits 5 for a key that already has a sha (WP-02), so the hint uses `--check`.
  - `Manual` names its `page` and `note`.
- **ApiError codes.** `From<FetchError>` is `ApiError::new(code, &e.to_string())`. UnknownKey → `not-found`. TbdAtPin, Manual, BadPin, Scheme → `refused`. Command, SizeMismatch, ShaMismatch → `command-failed`. Io → `io`. This is the only fetch→ApiError mapping (§2). All 8 codes stay the locked set (`api_response.rs:10-11`), and no code is added (D6).
- **Downloads.** Tests never download anything.
