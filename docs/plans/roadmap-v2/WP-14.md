**Behaviour**
- **Errors.** Every `Err(String)` that `settings_from`, `extras_from` or `apply_with` returns starts with one of the 8 locked codes and `": "` (`ERROR_CODES`, api.rs:77). WP-27 splits on that prefix. No new code is added (ruling D6). Each error that has one fix names the command that fixes it.
- **`settings_from`.**
  - `uevr-rendering`: `native` (default) or `synced`.
  - `uevr-2d-screen`: `yes` or `no` (default `no`).
  - Any other value gives `Err("bad-recipe: <key> must be …")`, listing the allowed values.
- **`extras_from`.**
  - `uevr-exe` is required (`Err("bad-recipe: uevr-exe is missing")`).
  - `uevr-delay` is a u32 from 0 to 120, default 15.
  - `uevr-native-stereo-fix`: `yes` or `no`.
  - `uevr-profile`: a `packaging/pins` key matching `[a-z0-9-]+` (for example `ac7-profile`). Any other value gives `Err("bad-recipe: uevr-profile must be a pin key ([a-z0-9-]+)")`. It is only carried here: WP-27 fetches that pin, resolving its url and sha256 from `packaging/pins`. `apply_with` does not copy the fetched profile into the prefix. That is outside this pass; do not build it and do not file an issue for it.
  - Both fns ignore keys outside `UEVR_KEYS`.
- **`profile_text_full`.** `profile_text(s)`, then optionally `VR_NativeStereoFix=true|false\n`, then `Frontend_RequestedRuntime=openxr_loader.dll\n`.
- **`apply_with`.** Nothing is written before step 5.
  1. `settings_from` and `extras_from`; an Err is returned as is.
  2. `compatdata = game.install_dir.parent().and_then(Path::parent).map(|s| s.join("compatdata"))`, that is `<lib>/steamapps/compatdata`. If that is None, `Err("not-found: game folder <dir> is not under steamapps/common")`. Do not call any `steam::compatdata` helper: WP-07 adds it in this same wave, so it is not there yet.
  3. Require both `UEVR_DLLS` in `uevr_dir(p)`, else `Err("not-found: UEVR is not fetched; run flat3d-inject setup fetch uevr")`. Require `injector_path(p)`, else `Err("not-found: flat3d-uevr-inject.exe is not installed; run tools/build-win.sh --install")`.
  4. `dir = profile_dir(compatdata, appid, exe_stem)`. The same marker and backup guard as `apply` (`uevr.rs:81-90`). A second apply gives `Err("refused: the UEVR profile for <appid> is already set up; run flat3d-inject undo <appid> first")`. The legacy `apply` keeps its locked text.
  5. Write with `profile_text_full`, then roll back on failure. A failed write gives `Err("io: …")` with the path and cause. The record has `launch_options_before = ""` (OD5).
  6. `RouteEnv{ env: [("PROTON_REMOTE_DEBUG_CMD", debug_cmd(..))], unset: ["XR_RUNTIME_JSON"], sidecar: None }`. `uevr::Applied.env` = `route_env.env.clone()`.
- **`debug_cmd`: the one argv contract.** This text is the only statement of what the injector receives. WP-15 (its argv parse) and WP-27 (the env it stores) point here and do not restate it. The golden file `crates/engine/tests/fixtures/uevr-debug-cmd.txt` holds it: line 1 is the `debug_cmd` string for the fixed inputs below, and each later line is one token of `shlex.split` of line 1. WP-15's args test reads that file with `include_str!`; no new Cargo dev-dependency is needed, because Cargo.lock is frozen.
  - Every path argument the injector receives is a Windows path, `win_path(..)` = `Z:` + the absolute Unix path with `/` replaced by `\`. Proton's `Z:` maps `/`. `--dll` takes full `Z:\` paths, because `LoadLibraryW` with a bare name searches the game's folder.
  - The one exception is `cmd[0]`, the injector itself. Proton is the one that runs it, not the injector, and it stays the absolute Unix path (see Review note).
  - Quoting is for Python `shlex.split` (POSIX mode, where backslashes inside `'…'` stay literal). The injector path, the stem and each `--dll` value are single-quoted, and an embedded `'` becomes `'"'"'`. `--exe`, `--delay`, `--dll` and the delay digits stay bare. The result is:

  ```
  '/…/flat3d/bin/flat3d-uevr-inject.exe' --exe 'SWZeroCompany' --delay 15 --dll 'Z:\…\uevr\<ver>\openxr_loader.dll' --dll 'Z:\…\uevr\<ver>\UEVRBackend.dll'
  ```

- Stems: `SWZeroCompany` (2075800) and `Ace7Game` (502500). Two SWZeroCompany.exe files exist, so the injector (WP-15) picks the image path that contains `\Binaries\Win64\`. The profile folder stays `UnrealVRMod/<stem>/`.
- Proton 11 (`proton:2023-2026,2100-2133`, verified locally at `Proton 11.0/proton:2102-2103`) `shlex.split`s `PROTON_REMOTE_DEBUG_CMD`.
  - If `cmd[0]` fails `os.path.isabs`, Proton rewrites it to `g_proton.path(cmd[0])`.
  - It runs `[wine]+cmd` before the game, with the same env and wineserver, and kills it when the game exits.
- `XR_RUNTIME_JSON` bypasses `active_runtime.json`, so it must be unset (SpidyVR `--unset-env=XR_RUNTIME_JSON`).
- The UEVR frontend defaults to OpenVR. With `Frontend_RequestedRuntime` set and `openxr_loader.dll` loaded first, the backend skips OpenVR (VR.cpp:107-120,251-252).
