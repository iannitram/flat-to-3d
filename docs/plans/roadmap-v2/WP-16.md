### WP-16: Geo-11 route pure half
**Refs:** #52 (code half). Not `Closes`: the issue is closed when its Q9 device session passes (ruling D5).
**Files:** `crates/engine/src/injectors/geo11.rs` (WP-01 leaves it an empty stub), `crates/engine/tests/geo11.rs`.

**Signatures**

`cache_dir` is always the engine cache root, `p.cache()` (WP-27 passes `&p.cache()`), never one pin's own folder. Below, `<cache>` means that argument.

```rust

use flat3d_viewer::spec::{Layout, ViewerSpec};
use crate::api::ApiError;
use crate::injectors::RouteEnv;
```

There is no local `RouteSettings` type and no local `KEYS` const: `recipes.rs` is the single owner of route keys (§2). `ApiError` is the existing struct `{code, message}` with `ApiError::new` (api.rs:89-101). It has no variants and no `Display`. `ViewerSpec: Default` and `RouteEnv{env, unset, sidecar}` are frozen by WP-01 (§2).

**Behaviour**
- **Error strings.** Every `Err(String)` this file returns starts with a code from `ERROR_CODES` (api.rs:77) and `": "`. The codes stay the locked 8 (ruling D6):
  - `bad-recipe`: a bad route value in `from_route`, and a d3dx.ini key with no line and no known section (`d3dx_patch`);
  - `not-found`: a missing exe, a missing fix or geo11 cache, a missing viewer;
  - `refused`: the game is already set up;
  - `io`: a file system failure during `apply` (after the rollback).
  - WP-27's `ensure_applied` passes `apply`'s String through unchanged, and `inject` splits on the prefix (WP-27 "Error mapping"). WP-16 owns the prefix; WP-27 does not add one.
- **`from_route`**
  - The value rules are the ones in §2's `check_route_settings` table. `from_route` also parses the values into types.
  - `geo11-layout` must be one of `sbs|tab|sbs_reversed|tab_reversed`. The error lists them.
  - `geo11-separation` is 0..=100. `geo11-convergence` is an f32 > 0.
  - `geo11-d3dx` has the form `k=v;k=v`. A part without `=` is an error. The pairs are appended after `force_stereo=2`.
  - `geo11-remove-first` is `;`-separated relative paths. Absolute paths and `..` are errors.
  - Keys outside `GEO11_KEYS` are ignored. `geo11-exe` and `geo11-fix` are not in `Geo11Settings`; `plan_files` reads them from the map.
- **`d3dxdm_text`** returns `direct_mode=<m>\ndm_separation=<n>\ndm_convergence=<c>\n`. `<c>` uses `{:.1}` when the value is whole, otherwise `{}`: 2.0 gives "2.0" and 2.25 gives "2.25".
- **Ini set rule**, shared by `d3dx_patch` and the d3dxdm.ini write:
  - Replace the first active `key<sep>value` line, comparing the key without ASCII case and keeping the original `<sep>` (for example ` = `).
  - Otherwise, insert the line after a commented `;key...` line.
  - Otherwise, in d3dx.ini, insert it after a known section header: `force_stereo`→`[Stereo]`, `get_resolution_from`→`[Device]`. If that section is missing, append it.
  - Otherwise, in d3dxdm.ini, append the line at the end of the file. Its keys (`direct_mode`, `dm_separation`, `dm_convergence`) have no known section.
  - Otherwise return `Err("bad-recipe: <file> has no <key> line")`, where `<file>` is the real file name. Because of the append rule above, only `d3dx.ini` can reach this.
  - Keep CRLF if the input uses it. Patching twice gives the same text as patching once.
- **`plan_files`**
  - It calls `Geo11Settings::from_route(m)` first and returns its Err as is.
  - A map with no `geo11-exe` gives `Err("bad-recipe: geo11-exe is missing")`.
  - The exe is `game_dir/<geo11-exe>`, which must exist, else `Err("not-found: …")` naming the path. The exe dir `E` is its parent.
  - **Depth:** in the two searches below, the starting directory (`<cache>/<key>/`) is depth 0 and its direct children are depth 1. Directories are walked in sorted path order, so a tie at one depth goes to the first path.
  - **Removes:** `Remove(E/<p>)` for each remove-first path that exists.
  - **Fix root:** `<cache>/<geo11-fix>/` holds the unpacked tree (the real one sits one level down, in the `<version>` folder that fetch adds). The fix root is the shallowest directory (depth ≤ 3) that holds `d3dx.ini`, else the shallowest one that holds `d3d11.dll`. Every file under it becomes a `Copy` to `E/<rel>`, except root-level `uninstall*.bat`, `readme*`, `*.url` (names compared without ASCII case) and `.flat3d-fetch` (the fetch marker). A map with no `geo11-fix` key means there is no fix: skip this step and use the overlay alone.
  - **Geo-11 overlay:** when the fix root has no `d3dxdm.ini`, or there is no fix at all, overlay `d3d11.dll`, `nvapi64.dll` and `d3dxdm.ini` from the overlay dir. The overlay dir is the first `x64` directory at depth ≤ 3 under `<cache>/geo11/`, in sorted path order. The overlay wins over the fix's copies. `d3dx.ini` comes from x64 only when the fix lacks one.
  - **Missing caches:** `Err("not-found: <key> is not fetched; run flat3d-inject setup fetch <key>")`, with `<key>` the missing pin key. For the `geo11-fix` value: `<cache>/<value>/` is missing or has no fix root. For `geo11`: the overlay is needed and `<cache>/geo11/` has no `x64` directory at depth ≤ 3.
  - **Name case:** if `E` already holds a file whose name matches the destination ignoring case, use that existing name.
  - **ini files:** `d3dx.ini` and `d3dxdm.ini` become `Write` steps with the patched text instead of `Copy`.
  - **Order:** Removes, then Copies sorted by `to`, then Writes.
- **`viewer_check`** is called by `apply` first, before anything else is touched: `viewer_check(viewer_exe).map_err(|e| format!("{}: {}", e.code, e.message))?`. It stays `pub` (§2), but no other caller is required in this pass. Callers pass `p.viewer_bin()` (§2). A missing viewer is never a silent fallback to flat.
- **`apply`**
  - Order: `viewer_check`, then `plan_files` (both only read), then the already-set-up check, then the writes.
  - `marker = E/.flat3d-applied` (`uevr::MARKER_FILE`). If the marker exists, or any `*.flat3d-backup` exists in `E`, return `Err("refused: Geo-11 is already set up in <E>; undo it first: flat3d-inject undo <appid>")`.
  - Write the marker and record it in `created`.
  - **Remove steps** rename `E/<p>` to `E/<p>.flat3d-backup` and record `Replaced{path, backup}`.
  - **Overwrite steps** (a Copy or Write whose target exists) back up the old file the way `uevr::write_all` does (uevr.rs:116-121): `fs::copy` it to `<name>.flat3d-backup.partial`, then `fs::rename` that to `<name>.flat3d-backup`, and record `Replaced`. If either step fails, remove the partial file. Then write the new file. `fs::copy` fails when the target is a directory, so a directory at the destination makes `apply` fail. A rename would succeed on Linux and hide it.
  - New files go in `created`. Directories are created but **not recorded**, because `undo_game` removes entries with `fs::remove_file` (undo.rs:226) and a recorded directory would break undo.
  - On any error, call a private `fn rollback(&UndoRecord)` and return Err. It renames each `Replaced` backup over its path in reverse order, then removes each created file in reverse order (the same steps as the private `uevr.rs:133` rollback, written here because that one is private). Directories created by the failed apply stay.
  - After undo, created directories (for example `ShaderFixes/`) are left in place and empty. Removing them would need a `RemoveDir` undo action, which is not in this pass.
  - `launch_options_before = ""` (OD5).
  - `RouteEnv.env = [("WINEDLLOVERRIDES","d3d11,nvapi64=n,b")]`, or `"d3d11,nvapi64,dxgi=n,b"` when a step writes `E/dxgi.dll`. `unset = []`. Merging with an inherited `WINEDLLOVERRIDES` is WP-31's job, not this file's.
  - `sidecar = Some([viewer_exe.to_string_lossy().into_owned()] ++ ViewerSpec{layout, ..ViewerSpec::default()}.to_args())`. WP-31 appends `--until-pid <pid>`.

**Tests** (`tests/geo11.rs`, fake trees under `env!("CARGO_TARGET_TMPDIR")`, no download)
- **Snapshot:** the sorted list of (relative path, bytes) of regular files only; directories are ignored. The rollback, second-apply, missing-viewer and undo checks all use it.
- **Fixtures:**
  - `geo11/geo-11_v0.7.12/x64/d3dxdm.ini` = `"direct_mode=sbs\ndm_separation=30\ndm_convergence=1.0\n"`. The x32 files contain `"x32"`, so a wrong pick is visible.
  - `control-fix/d3dx.ini` = `"[Stereo]\nforce_stereo = 0\n[Device]\n;get_resolution_from = depth_buffer\n"`.
  - Lana: `lana-fix/Planet of Lana/{d3dx.ini,d3d11.dll,d3dxdm.ini}`. The fix root sits one level down, so this exercises the depth rule.
- `d3dxdm_text`: the default is exact; all 4 layouts map to the right `direct_mode`; convergence 2.25 prints as "2.25".
- `from_route`: an empty map gives the default. Each of these is an error: `interlaced`, separation 101, convergence 0, d3dx `nokey`, remove-first `../x`.
- `d3dx_patch`:
  - `force_stereo = 0` becomes `force_stereo = 2`.
  - A commented line gets the active line inserted after it.
  - A missing `[Stereo]` section is appended.
  - CRLF is kept. Patching is idempotent.
  - An unknown key with no line gives Err.
- **`error_cases`** (table-driven): each row is a setup and its expected code. Every Err starts with `<code>: ` and the code is in `ERROR_CODES`.
  - layout `interlaced`, d3dx `nokey`, and `d3dx_patch` with an unknown key → `bad-recipe`;
  - a missing exe → `not-found`;
  - a missing `geo11` cache → `not-found`, and the message contains `setup fetch geo11`;
  - a missing fix cache → `not-found`, and the message contains `setup fetch control-fix`;
  - a missing viewer → `not-found`;
  - a second apply → `refused`, and the message contains `flat3d-inject undo <appid>`;
  - the rollback case below → `io`.
- **Control:**
  - Cache: `control-fix/{d3dx.ini,d3d11.dll,ShaderFixes/a-ps.txt,uninstall.bat}` and `geo11/geo-11_v0.7.12/{x64,x32}/{d3d11.dll,nvapi64.dll,d3dxdm.ini}`. The game dir holds `Control_DX11.exe` and `dxgi.dll`.
  - Route: `geo11-fix: control-fix`, `geo11-exe: Control_DX11.exe`, `geo11-d3dx: get_resolution_from=swap_chain`, `geo11-remove-first: dxgi.dll`.
  - Expected steps: `Remove(dxgi.dll)` comes first; there is no `uninstall.bat`; `d3d11.dll` comes from x64 (not from the fix or from x32); a `d3dx.ini` Write contains both keys.
- **Lana:** the fix tree has its own `d3dxdm.ini`, so no geo11 cache is needed. No step's `from` is under `<cache>/geo11`, and there is a `d3dxdm.ini` Write with `direct_mode=sbs`.
- **Missing viewer:** `viewer_check(<tmp>/nope)` is `Err(e)` with `e.code == "not-found"` and `e.message` containing `flat3d-viewer not found`. A regular file with no x bit is also `not-found`. `apply` with the missing path gives an Err starting `not-found: ` and containing `flat3d-viewer not found`. The snapshot is unchanged and no marker is written.
- **apply → undo:**
  - Write `record.to_text()` to `undo::record_path(data, appid)`, then call `undo::undo_game`.
  - Afterwards the snapshot equals the one taken before, and `dxgi.dll` is restored.
  - `E/ShaderFixes/` still exists and is empty (directories are not recorded).
  - The env is exact.
  - The sidecar equals `[viewer] ++ spec.to_args()`, with `viewer` as `to_string_lossy()`. The fake viewer is an executable empty file.
- A second apply gives Err, with the snapshot unchanged.
- A fix that ships `dxgi.dll` gives `d3d11,nvapi64,dxgi=n,b`.
- Rollback: in the Control tree, when `E/d3d11.dll` is a directory, apply gives Err (the backup `fs::copy` fails) and the snapshot is unchanged. `ShaderFixes/` may remain, and the snapshot ignores it.

**Inline facts**
- Pin keys: `geo11` (0.7.12), `lana-fix`, `control-fix` (`packaging/pins`, WP-02). `fetch::cache_dir` is `p.cache()/<key>/<version>` (§2), so the depth-≤3 searches allow for the version dir.
- Use the x64 `d3d11.dll`, `nvapi64.dll` and `d3dxdm.ini`, with `force_stereo=2`.
- Control: `get_resolution_from = swap_chain`, and remove HelixSR's `dxgi.dll` first.
- Proton appends a user `WINEDLLOVERRIDES` after its own.
- `undo.rs` today: `UndoRecord{appid, launch_options_before, created, replaced}`, `Replaced{path, backup}`, `record_path`, `to_text`, `undo_game` (undo.rs:10-28, 102, 177, 201).
- Viewer shipping (other WPs' files): WP-20 `install` copies `flat3d-viewer` into `paths.bin` (`optional_bins`). WP-22 bundles it in `bin/` of both the AppImage and the Decky zip (`PAYLOAD_BIN`). WP-27 passes `p.viewer_bin()` as `viewer_exe`. Without all three, `viewer_check` fails on every Geo-11 launch.
