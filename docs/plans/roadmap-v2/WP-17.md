**Behaviour**
- **`eye_rects`**
  - `half = w/2`. Sbs gives `[(0,0,half,h),(half,0,half,h)]`; an odd last column is dropped.
  - Tab splits on `h/2` the same way.
  - SbsRev and TabRev swap the pair. `swap_eyes` then swaps it again.
  - `crop_aspect = Some(a)` with `a > 0` crops each eye to the centred `a` aspect, in pixels:
    - if `w/h > a`: `nw = round(h*a)`, `x += (w-nw)/2`;
    - otherwise `nh = round(w/a)`, `y += (h-nh)/2`.
  - `crop_aspect` is a pixel aspect, which is FlatToDepth's meaning.
  - A zero-sized frame gives `[Rect::default(); 2]` and never panics.
- **`unsqueeze`** exists because Geo-11's on-screen SBS is half-width, so quads sized from raw pixel rects would show at half aspect. `ViewerSpec` has no half/full field, so WP-19 calls `unsqueeze` for screen capture.
- **`State::as_str`**: `WaitingHeadset`→`"waiting-headset"`, `WaitingSource`→`"waiting-source"`, `Showing`→`"showing"`, `Error`→`"error"`. WP-19's status lines use these strings.
- **`to_line`** writes `{"state":"showing","fps":59.9,"w":1920,"h":1080}`:
  - fps uses `{:.1}`, and a value that is not finite becomes `0.0`;
  - there is no trailing newline;
  - it is hand-formatted, because the viewer has `serde` but no `serde_json`.
- **`from_line`** parses exactly that shape: key order is fixed and whitespace is tolerated. An unknown state is an Err.
- **`TestPattern::next`**
  - Returns `Frame{width:w, height:h, fourcc: u32::from_le_bytes(*b"XR24"), seq, data: FrameData::Mem{stride: 4*w, bytes}}`. `XR24` is XRGB8888, which is BGRx bytes in memory.
  - Draw order: grey fill `[64,64,64,255]`, then the liveness row, then the bar, then the marks last.
  - In each eye rect from `eye_rects` it draws:
    - a white `[255,255,255,255]` 2-px liveness row at `y = seq % rh` (rows `y` and `y+1`);
    - a white vertical bar `max(1,rw/32)` wide, the full rect height, at `rx + rw/2 ± rw/64` (+ in the left eye, − in the right), so the disparity is visible;
    - an 8×8 mark at the rect's top-left (+2,+2): `LEFT_MARK` in the left eye, `RIGHT_MARK` in the right.
  - It skips an eye whose rect has `rw == 0` or `rh == 0`, so `seq % rh` never divides by zero. It clips the row, the bar and the mark to the eye rect.
  - It increments `seq` after each returned frame.
  - Pacing: `new()` sets `next_at = Instant::now()`, so the first call returns at once. With `fps > 0`, it sleeps until `next_at`. If `next_at` is later than now + `timeout`, it sleeps for `timeout` and returns `Ok(None)`; `Ok(None)` does not increment `seq`. After returning a frame, `next_at += Duration::from_secs(1)/fps`.
- `Frame` has no `Clone`, so tests compare fields, never whole frames.

**Tests**
- **`crates/viewer/tests/layout.rs`:**
  - Sbs 1920×1080 → `[(0,0,960,1080),(960,0,960,1080)]`.
  - Tab → `[(0,0,1920,540),(0,540,1920,540)]`.
  - SbsRev and TabRev are swapped.
  - `swap_eyes` on Sbs equals SbsRev; on SbsRev it equals Sbs.
  - Odd width 1921 → both eyes are 960 wide.
  - **FlatToDepth vector:** 10240×1440 Sbs with `crop_aspect = 16.0/9.0` → `[(1280,0,2560,1440),(6400,0,2560,1440)]`, which is columns 1280–3839 of each 5120-wide eye. With `swap_eyes` the pair is reversed; that is the inverted-depth fix.
  - Crop of a tall eye: frame 1920×1080 Sbs with 16:9 → `[(0,270,960,540),(960,270,960,540)]`.
  - `crop_aspect` None or 0 → no crop. 0×0 → defaults.
  - `quad_size((0,0,2560,1440),3.0) == (3.0,1.6875)`. `unsqueeze(960×1080, Sbs)` → 1920×1080.
  - **TestPattern** 64×32 Sbs, fps 0:
    - `width==64`, `height==32`, `fourcc==u32::from_le_bytes(*b"XR24")`, `FrameData::Mem` with stride 256 and 8192 bytes;
    - the pixel at (2,2) is `LEFT_MARK` and the one at (34,2) is `RIGHT_MARK`, on both seq 0 and seq 1 (the marks are drawn last);
    - with SbsRev the two are swapped;
    - `seq` is 0, then 1.
  - TestPattern 1×1 and 0×0 → no panic.
  - fps 1 with a 10 ms timeout: the 1st call is `Some`, the 2nd is `Ok(None)` within 200 ms.
- **`crates/viewer/tests/status.rs`:**
  - The exact line for each of the 4 states, e.g. `{"state":"waiting-headset","fps":0.0,"w":0,"h":0}`, `{"state":"waiting-source","fps":0.0,"w":0,"h":0}`, `{"state":"showing","fps":59.9,"w":1920,"h":1080}`, `{"state":"error","fps":0.0,"w":0,"h":0}`.
  - 59.94 → `59.9`; NaN → `0.0`. These two assert the line only.
  - Round trip through `from_line` for one-decimal fps values only (59.9, 0.0).
  - `{"state":"bogus",...}` → Err; `""` → Err.

**Inline facts**
- FlatToDepth (MIT, Blackskydk/FlatToDepth `docs/assessment.md`):
  - each eye is 5120×1440, and the picture fills columns 1280–3839 ("crops to the centred 16:9 region");
  - `swap_eyes=1` fixed the inverted depth;
  - the quad sits 2.5 m away, and its width is clamped to 0.3–20 m.
