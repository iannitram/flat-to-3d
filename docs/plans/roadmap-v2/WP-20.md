**Behaviour**
- `unit_text_with(&UnitSpec::default())` is exactly:
  `"[Unit]\nDescription=Flat to 3D headset link\nStartLimitIntervalSec=60\nStartLimitBurst=10\n\n[Service]\nType=simple\nExecStart=%h/.local/bin/flat3d-inject watch\nRestart=on-failure\nRestartSec=3\n\n[Install]\nWantedBy=default.target\n"`
  - `Description`, `ExecStart`, `RestartSec`, the two `StartLimit*` values and `WantedBy` come from the spec. `Type=simple` and `Restart=on-failure` are fixed text. `StartLimit*` belong in `[Unit]`.
  - No `KillMode`: the default `control-group` is documented by WP-02 in packaging/README.
  - No linger.
  - `unit_text`, `unit_path`, `bin_dir`, `UNIT_NAME` and the existing fields of `install_plan`/`uninstall_plan` stay as they are (locked install_plan.rs:14-72). The locked `copies` list stays exactly 5 entries and `removes` stays 6.
- `packaging/flat3d-link.service` is byte-equal to `unit_text_with(&UnitSpec::default())`.
- `install_roots(home)` (private) is the one list of places install may write and uninstall may remove: `{home}/.local/bin/`, `{home}/.local/share/flat3d/`, `{home}/.config/systemd/user/`. A path is inside the roots only when it starts with one of them and has no `..` component. Install and uninstall both use this fn; neither keeps its own list.
- `install_plan(home, src)` also fills:
  - `home`;
  - `dirs = [{home}/.local/bin, {home}/.local/share/flat3d/bin, {home}/.local/share/flat3d/recipes, {home}/.config/systemd/user]`;
  - `optional_bins = [({src}/flat3d-viewer, {home}/.local/bin/flat3d-viewer)]`. The viewer goes into `paths.bin` next to `flat3d-run`, so WP-16's `viewer_check` finds it after a normal install. It is not in the locked `copies` list;
  - `trees = [({src}/tools/lib, {home}/.local/share/flat3d/bin/lib), ({src}/recipes, {home}/.local/share/flat3d/recipes)]`;
  - `manifest = {home}/.local/share/flat3d/installed.txt`.
- `uninstall_plan(home)` also fills `home` and the same `manifest`.
- `execute`, in this order:
  1. Check every destination (`copies`, `optional_bins`, each tree's destination dir, `unit_path`, `manifest`) is inside `install_roots(plan.home)`. One that is not → `Err(ApiError::new("refused", "<path> is outside the install folders; fix: build the plan with install::install_plan(home, src_dir)"))`, before anything is written or run.
  2. Check both binary sources exist (`copies` whose file name is `flat3d-inject` or `flat3d-run`). A missing one → `Err(ApiError::new("io", "missing <src path>; fix: run flat3d-inject install from the release folder that holds flat3d-inject and flat3d-run"))`, before anything is written or run.
  3. `fs::create_dir_all` on each of `dirs`.
  4. Copy the binaries (`fs::copy`), mode `0o755`.
  5. Copy the other `copies` (tools) and `optional_bins`. A missing source is skipped. The skipped file names go in the summary as one note, `"not bundled: adb, gnirehtet, flat3d-viewer"` (plan order; ruling 34: the running adb is preferred). `adb`, `gnirehtet` and `flat3d-viewer` get `0o755`, `gnirehtet.apk` gets `0o644`.
  6. For each tree whose source dir exists: create the destination dir, then copy the regular files one level deep (no recursion). For the recipes tree copy only `*.recipe`. Lib files get `0o755`, recipes `0o644`.
  7. Write `unit_text_with(&UnitSpec::default())` to `plan.unit_path` atomically: write `{unit_path}.tmp`, then `fs::rename`. Never `plan.unit_text`.
  8. Write the manifest: every destination file written in steps 4-7, one absolute path per line, `\n`-terminated.
  9. Run `plan.commands` in order. A non-success → `Err(ApiError::new("command-failed", "<argv joined by ' '>: <last non-empty stderr line>; fix: read systemctl --user status flat3d-link.service, then re-run flat3d-inject install"))`. The files stay in place and later commands do not run.
  10. Return `InstallReport{written, ran, summary}`: `written` = every file written, the manifest last; `ran` = each command's argv joined by `" "`; `summary` = the notes joined by `"; "`, or `""` when there are none.
  - Any fs error in steps 3-8 → `Err(ApiError::new("io", "<path>: <err>; fix: make that folder writable, then re-run flat3d-inject install"))`.
  - **The manifest is written even when install fails partway.** If steps 3-7 fail after at least one file was written, execute first writes the manifest with the files written so far, then returns the error. A failure to write that manifest does not replace the first error. So `uninstall` can always clean up a half install.
- `execute_uninstall`:
  1. Run each of `before`. A non-success is tolerated, since the unit may not exist; it adds the note `"tolerated <argv joined>: <last stderr line>"` to the summary. It still goes in `ran`.
  2. The removal set is `removes`, then each manifest line (if the manifest exists), then the manifest itself. Each path is removed with `fs::remove_file`; `NotFound` is ignored. Another error → `Err(ApiError::new("io", "<path>: <err>; fix: remove that file by hand, then re-run flat3d-inject uninstall"))`. Each actual removal goes in `written` (the paths touched).
  3. A path is removed only when it is inside `install_roots(plan.home)`. Any other path is skipped with the note `"refused <path>"`. This is what keeps `{home}/.config/flat3d/…` and `{home}/.local/state/…` safe: never touch `~/.config/flat3d` or `~/.local/state`.
  4. Run each of `after`. A non-success → `Err(ApiError::new("command-failed", "<argv joined>: <last non-empty stderr line>; fix: run systemctl --user daemon-reload"))`.
  5. Return `InstallReport{written, ran, summary}` as in execute.
- The fix clauses above are fixed text: each is a private const in `install.rs`, and none points at `doctor` (WP-29 comes later, in wave 4).
- `add_wrapper_at(options, wrapper_abs)`:
  - If `wrapper_abs` contains whitespace or `"`, or its last `/` segment is not `WRAPPER` (`flat3d-run`) → return `add_wrapper(options)`. This bare fallback means `remove_wrapper` can always find the wrapper.
  - If `has_wrapper(options)`: with the same `words()` split, replace the first wrapper word before `%command%` (or before the end when there is no `%command%`) with `wrapper_abs`, drop any further wrapper words before that point, and join with `" "`. This upgrades bare to absolute and is idempotent.
  - Otherwise do exactly what `add_wrapper` does, with `wrapper_abs` in place of `WRAPPER`: after any leading env words, or `wrapper_abs %command% <rest>` when `%command%` is absent.
  - `remove_wrapper` is unchanged: `is_wrapper` already matches the last path segment (base launch_options.rs:51-53; locked tests/launch_options.rs:50-52).
  - `add_wrapper`, `has_wrapper`, `remove_wrapper` and `WRAPPER` keep their bodies (locked launch_options.rs, unlocked launch_options_quotes.rs).
