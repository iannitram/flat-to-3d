### WP-22: Packaging scripts (#127/#129/#134)
**Closes:** nothing outright. The PR says `Refs #127, #129, #134 (code half)`, because Q1, Q14 and Q16 hold the device halves (see PR below).
**Files (exclusive):** `packaging/lib.sh`, `packaging/build-tools.sh`, `packaging/build-appimage.sh`, `packaging/AppRun`, `packaging/flat3d.desktop`, `packaging/build-decky.sh`, `packaging/tests/test_packaging.py`, `.github/workflows/appimage.yml`.

**Interfaces.** Every script is bash with `set -euo pipefail`, clean under shellcheck, and starts with `. "$(dirname "$0")/lib.sh"` (with a `# shellcheck source=lib.sh` directive). `packaging/lib.sh` is sourced, never run, and holds the one copy of:
- `ROOT=$(cd "$(dirname "${BASH_SOURCE[0]}")/.." && pwd)` and `PINS=${PINS:-$ROOT/packaging/pins}` (`--pins FILE` overrides it).
- `pin(){ local v; v=$(grep -m1 "^$1: " "$PINS" | cut -d' ' -f2-) || v=; if [ -z "$v" ] || [ "$v" = TBD-at-pin ]; then echo "pin $1 missing or TBD-at-pin: fix: packaging/pin.sh ${1%.*}" >&2; exit 2; fi; printf '%s\n' "$v"; }`. The `|| v=` matters: under `set -euo pipefail` a missing key makes `grep` exit 1, which would otherwise kill the script with exit 1 and no message.
- `run(){ printf '+'; printf ' %s' "$@"; printf '\n'; [ "${DRY:-0}" = 1 ] && return 0; "$@" || { echo "step failed: $*" >&2; exit 1; }; }`. Every step goes through `run`. It prints the raw argv, so `$ORIGIN` appears literally in a dry run. The two exceptions are the sha check (exit 4) and the final checks (exit 1): each prints its `+` line the same way, only prints in a dry run, and exits with its own code.
- The **PAYLOAD** table, the one list both faces (AppImage and Decky zip) ship:
  - `PAYLOAD_BIN=(flat3d-inject flat3d-run flat3d-viewer)`, copied from the cargo bin dir, mode 0755;
  - `PAYLOAD_TOOLS=(adb gnirehtet gnirehtet.apk)`, plus `lib/*`, copied from `--tools`. This matches install_plan's tool list (crates/engine/src/install.rs, today inject/src/install.rs:36).
  - `flat3d-app` is AppImage-only, so it is not in the table.
- The pin keys used are `android-tools.{version,url,sha256}`, `gnirehtet.{version,url,sha256}`, `appimagetool.{url,sha256}` and `appimage-runtime.{url,sha256}`.
```
packaging/build-tools.sh    [--dry-run] [--no-box] [--pins FILE] [--out DIR=$ROOT/dist/tools]
packaging/build-appimage.sh [--dry-run] [--no-tools] [--tools DIR=$ROOT/dist/tools] [--bin-dir DIR] [--skip-build] [--pins FILE] [--out FILE=dist/Flat_to_3D-x86_64.AppImage]
packaging/build-decky.sh    [--dry-run] [--no-tools] [--tools DIR=$ROOT/dist/tools] [--bin-dir DIR] [--root DIR=$ROOT] [--skip-build] [--out FILE=dist/flat-to-3d.zip]
```
The default `--bin-dir` is `${CARGO_TARGET_DIR:-$ROOT/target}/release`.

**Exit codes** (all three scripts; per tool, as §2 says):

| Exit | Meaning | Message names the fix |
|---|---|---|
| 0 | done, or `--dry-run` printed every step | — |
| 1 | a step run through `run` failed (`step failed: <argv>`), or a final check failed | the failing argv |
| 2 | usage: an unknown flag or a missing flag value (prints the usage line); or a pin missing or `TBD-at-pin` | `fix: packaging/pin.sh <key>` |
| 3 | preflight: required tools missing (build-tools.sh) | `fix: run inside the craft-build box (drop --no-box), or install: <list>` |
| 4 | a downloaded file's sha256 does not match its pin | `fix: packaging/pin.sh <key> --check` |

**Behaviour**
- **Order, every script:**
  1. Parse args (exit 2 on a bad flag).
  2. Read every pin it needs (exit 2).
  3. If `--dry-run`: set `DRY=1`, print every step with placeholder dirs (`$CACHE/dl.XXXXXX`, `$tmp/AppDir`, `$stage`; no `mktemp`), and exit 0. A dry run checks nothing on disk, uses no network, enters no container and writes nothing, so it skips the box re-exec and the preflight.
  4. Otherwise do the steps below.
- **build-tools.sh** (#127, ruling 34).
  - Unless `--no-box`, `FLAT3D_IN_BOX=1`, or already inside a container (`/run/.containerenv`), re-exec via `distrobox enter "${FLAT3D_BUILD_BOX:-craft-build}" -- env FLAT3D_IN_BOX=1 bash "$0" "$@"`, where `"$@"` is the original argv, saved before parsing.
  - Preflight: `cmake ninja pkg-config patchelf unzip sha256sum curl ldd`. List what is missing and exit 3; it never installs anything.
  1. Fetch `android-tools.url` and `gnirehtet.url`, each into its own fresh `mktemp -d "${XDG_CACHE_HOME:-$HOME/.cache}/flat3d/dl.XXXXXX"`, using `curl -fL --proto '=https' --tlsv1.2 --retry 3 -o`. Then `echo "<sha>  <file>" | sha256sum -c`; a mismatch exits 4.
  2. `tar -xJf` the tarball, then `cmake -GNinja -S android-tools-<version> -B build -DCMAKE_BUILD_TYPE=Release && ninja -C build adb`. Find the binary with `find build -type f -name adb -perm -u+x`.
  3. Copy it to `$out/adb`. Copy its `ldd` closure into `$out/lib/`, minus `linux-vdso ld-linux-x86-64 libc libm libpthread libdl librt libudev`. Run `patchelf --set-rpath '$ORIGIN/lib' $out/adb` and `--set-rpath '$ORIGIN'` on each lib.
  4. `unzip -j -o <zip> '*/gnirehtet' '*/gnirehtet.apk' -d $out`, then chmod 755 adb/gnirehtet/lib and 644 the apk.
  5. Write `$out/SHA256SUMS`, listing at least `adb`, `gnirehtet` and `gnirehtet.apk`. The APK has no published hash, so its hash is recorded here rather than in pins.
  6. Verify: `$out/adb version` matches `Android Debug Bridge`, and `ldd $out/adb` has no `not found` (exit 1 otherwise).
- **build-appimage.sh** (#129).
  - Unless `--skip-build`: `cargo build --release --locked -p flat3d-inject -p flat3d-app`, then `cargo build --release --locked -p flat3d-viewer --features xr,capture`. The `capture` feature needs the pipewire, spa and clang headers, which the host lacks: on the host, build inside craft-build, or build there first and pass `--skip-build --bin-dir`.
  - Build the AppDir `$tmp/AppDir`:
    - `usr/bin/flat3d-app` and `usr/bin/<n>` for each `PAYLOAD_BIN` entry;
    - for each `PAYLOAD_BIN` entry a **symlink** `usr/<n> -> bin/<n>`, printed as `+ ln -s bin/<n> <AppDir>/usr/<n>`. install_plan reads `{src}/flat3d-inject` (crates/engine/src/install.rs, today inject/src/install.rs:34), and `fs::copy` follows links;
    - `usr/tools/` from `PAYLOAD_TOOLS` (from `--tools`, unless `--no-tools`);
    - `usr/recipes/`: always `mkdir -p`, then copy `$ROOT/recipes/*.recipe` under `shopt -s nullglob`. The repo has none today (recipes/ holds only README.md), so a bare glob would fail under `set -e`;
    - `AppRun`, `flat3d.desktop`, `flat3d.svg` and `.DirIcon -> flat3d.svg`. No WP's file list has an icon file, so the script writes `flat3d.svg` from a heredoc.
  - Fetch and verify `appimagetool.*` and `appimage-runtime.*` the same way as build-tools.sh, `chmod +x` the tool, then run `APPIMAGE_EXTRACT_AND_RUN=1 ARCH=x86_64 appimagetool --runtime-file <runtime> AppDir <out>`.
  - Bundle **no** wayland/xkbcommon/vulkan/GL/X11/drm/gbm/fontconfig libs (AppImage excludelist). Assert that no `*.so*` exists outside `usr/tools/lib` (exit 1 otherwise).
  - The tools live in `usr/tools/`, not `usr/share/flat3d/tools`. `FLAT3D_SRC_DIR=$APPDIR/usr`, together with install_plan's `{src}/tools/…`, needs `usr/tools/` plus the binary symlinks above.
