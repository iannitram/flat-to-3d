### WP-24: Session runner, stereo gates, device sessions

**Closes:** T9-T12. Gives every Q row (§5) its driver, Q0, Q2 and Q12 included.

**Refs:** #31, #5, #7, #155 (§5 Q5 and Q13 list WP-24 under "Needs WPs"). The PR writes `Refs #N`, never `Closes #N` (ruling D5). Each issue is closed by the owner or PM when its session passes.

**Files:** `tools/session/{session.py,test_session.py}`, `tools/stereo/{fps.py,disparity.py,test_stereo.py}`, `sessions/README.md`, and the **23** `sessions/*.toml` files in the index (20 game/app sessions plus `q0`, `q2`, `q12`).

Does not touch `docs/STEP0-RUNSHEET.md` (WP-25b hand-scrubs it, WP-34 generates it).

**Rules:**
- Python ≥3.11, stdlib only (`tomllib argparse subprocess shlex json zlib struct glob time os pathlib re shutil signal`). No numpy and no Pillow (buildenv §4d: neither exists anywhere).
- All tests are `unittest.TestCase` classes. The per-folder `unittest discover` loop does not collect plain pytest functions (WP-02).
- Network: read-only `gh issue view N --json body -q .body`, once per issue, to copy each Done-when verbatim (the §0 issue-snapshot pattern). For q0, q2 and q12, `done_when` is the §5 row's What and pass condition.
- Private words (WP-25a's `private` rule scans every tracked file outside `**/tests/**`):
  - The build container's name appears only on the single `FLAT3D_BUILD_BOX` line below.
  - `test_session.py` builds its home path at run time, as `"/home/" + "x"`.
  - session.py's own reject regex is written `r"/home/[^/\s{]+"`.
  - Done-when text that hits a private word gets that word replaced by "the owner".

**Signatures:**
```
session.py check [FILES...]            # default sessions/*.toml; exit 0 ok, 1 schema errors ("file: field: msg")
session.py render FILE [--out PATH]    # markdown runsheet to stdout, or to PATH; deterministic
session.py run FILE [--script ANSWERS.json] [--state-dir DIR] [--now UNIX] [--dry-run]
  # exit 0 PASS, 1 FAIL, 3 INCOMPLETE (a skip), 2 usage/IO
session.py pending [--state-dir DIR]   # sessions with no PASS result yet, in §5 Q order; exit 0
fps.py CSV [--min 30] [--skip-rows 0] [--json]                # exit 0 pass, 1 fail, 2 bad input
disparity.py IMG [--layout sbs|tab] [--block 16] [--step 64] [--max-shift 48] [--min-texture 20] [--min 1.0] [--json]
```
Python API (the tests import these):
- `load(path)->dict`, `validate(doc, path)->list[str]`, `render(doc)->str`
- `run(doc, answers:dict|None, state_dir:Path, now:int)->dict`
- `to_markdown(result)->str`
- `pending(docs:list[dict], state_dir:Path)->list[dict]`
- `fps.summarize(rows)->dict(n,p50,p1)`, `fps.read_mangohud(path)->list[tuple[float,float|None]]`
- `disparity.decode(path)->(w,h,luma:bytearray)`, `disparity.measure(w,h,luma,layout,...)->dict(n,mean,p90)`

**TOML schema (`schema = 1`):**
- Top level:
  - `name` (must equal the file stem), `title`, `issues=[int]` (the issues the result .md is pasted into; may be empty, as for q0 and q2), `spec=["M1"]`.
  - `q = "Qn"`: the §5 row this session drives. `check` rejects an id outside Q0-Q16.
  - `evidence_only=[int]` (optional, must be a subset of `issues`): issues that a PASS only gathers evidence for. These close only with the later works-now recipe PR, never by the session. When it is non-empty, `[vars].appid` is required.
  - `device` ⊆ {z13, quest2, build-box, ci}.
  - `done_when` (copied verbatim from the issue).
  - `after=[session names]` (each must exist), `needs=[str]` (prerequisites).
  - Optional `[vars]`: string constants.
  - `[[trouble]] symptom/cause`, rendered as the "If it fails" table.
- `[[step]]` fields:
  - `id` (unique, `[a-z0-9-]+`), `kind` = cmd | ask | check | measure, `who` = you | script, `text`, `section` = setup | each-run | check (default each-run).
  - cmd: `run=[argv]` (no shell), `ok_rc=[0]`, `timeout=120`, `expect` (stdout regex), `expect_json`, `expect_code`, `background=false` (Popen, killed at session end), `optional=false`.
    - `expect_json` is a table of JSON pointer → value, checked against the last stdout line parsed as a JSON object. Example: `expect_json = { "/ok" = true, "/data/ok" = true }`.
    - `expect_code` is a string: the step is ok only when that line is an error envelope whose `error.code` equals it.
    - Use `expect_json` and `expect_code`, not an `expect` regex, for `flat3d-inject --json` output.
  - check: `gate=true`, answered y/n/s.
  - measure: `tool` = fps | disparity, `args=[...]`, `input` (glob; the newest match is offered as the default answer), `optional=false`.
- Placeholders:
  - `{repo}` = `Path(__file__).resolve().parents[2]`, `{home}`, `{state}` = `${XDG_STATE_HOME:-~/.local/state}/flat3d`, `{data}` = `${XDG_DATA_HOME:-~/.local/share}`.
  - `{re_home}` = `$FLAT3D_RE_HOME` (default `~/.local/share/flat-to-3d`).
  - `{build_box}` = `os.environ.get("FLAT3D_BUILD_BOX", "craft-build")`. Keep this on one line, because the docs check allow-lists lines containing FLAT3D_BUILD_BOX.
  - `{<var>}`, and `{ans:<id>}` (an earlier answer).
  - `{{` and `}}` are literal braces.
  - Placeholders are filled only in `text`, `run`, `expect`, `input` and `args`, never in `done_when` or `trouble`.
  - An unknown placeholder is a `check` error.
- `check` also rejects, in `run`:
  - a literal `/home/<user>` or `sudo`;
  - a glob: an element with `*` or `?`, unless the element before it is `-name`, `-iname` or `-path`. There is no shell, so a glob never expands. Fix: `find … -name`.
- Each `check` error is `file: field: msg`. When one change fixes it, the message ends `(fix: …)`, for example `(fix: add vars.appid)` or `(fix: use find … -name)`.

**Run behaviour:**
- The working directory is `{repo}`. Walks the steps in order and prints each `text` with its placeholders filled.
  - A `who=script` cmd runs. It records rc, the last 20 lines of stdout and stderr, and `code` (the envelope's `error.code`, when the last stdout line is an error envelope).
  - A `who=you` cmd is printed, not run, and answered y/n/s (y = ok).
  - `expect` is checked with `re.search(expect, stdout, re.M)`.
  - A timeout counts as a fail. Build steps set a timeout that fits the build; the 120 s default is for quick probes.
  - A background cmd is ok when it is still alive 2 s after start. At session end it gets SIGTERM, then SIGKILL after 5 s.
  - A measure runs `sys.executable {repo}/tools/stereo/<tool>.py <input> --json <args>` and records its JSON.
- Answers:
  - Only ask, check and `who=you` cmd steps need an answer. A measure answer is optional: a path, or empty for the newest `input` match.
  - `--script` answers by step id. cmds still run. A missing answer exits 2 with `missing answer for step <id> (fix: add "<id>" to <ANSWERS.json>)`.
- `--dry-run` fills and prints every step. It needs no answers (`{ans:*}` prints literal), runs nothing and writes nothing. It checks that each `who=script` cmd's `run[0]` resolves with `shutil.which` when `run[0]` is a bare name. A `run[0]` with a `/` (such as `dist/tools/adb`, made by an earlier step) is printed, not checked. It exits 0, or 1 naming each command that does not resolve.
- Verdict:
  - PASS: every non-optional cmd ok, every gate check `y`, every non-optional measure pass.
  - INCOMPLETE: any `s` on a non-optional step.
  - FAIL: anything else.
  - An optional step that fails, is skipped, or (a measure) has no input is recorded but does not change the verdict.
- Writes `{state-dir}/<name>-<now>.json`. The default state-dir is `{state}/sessions` = `~/.local/state/flat3d/sessions/`.
  - Contents: `{schema, session, q, issues, evidence_only, started, ended, commit, dirty, os: PRETTY_NAME from /etc/os-release, verdict, steps:[{id,kind,who,status,answer,rc,code,tail,metrics}]}`.
  - `commit` is `git -C {repo} rev-parse HEAD` and `dirty` is whether `git -C {repo} status --porcelain` printed anything. Both are null when git fails.
  - `who` records who checked the step: `you` (the owner's answer) or `script`.
  - No hostname, because machine names are private.
- Also writes `<name>-<now>.md`, a paste-ready issue comment, and prints it. It has a header, `done_when`, the step table, and two sections:
  - `## Verified`: each ok step, with what proved it (rc, the expect match, the metric) and who checked it.
  - `## Not verified`: each skipped step, each optional step that failed or had no input, and each step not reached.
  - For each `evidence_only` issue it adds the line: "Evidence for #N. This does not close it: #N closes with the works-now recipe PR (`recipes/<vars.appid>-*.recipe`)."
  - The tool makes no GitHub writes.
- render:
  - Header `<!-- generated by tools/session/session.py render sessions/<name>.toml; edit the TOML -->`, then a one-line legend for the placeholders left unfilled.
  - It fills only `[vars]` and strips the `{repo}/` prefix. It leaves `{home}`, `{state}`, `{data}`, `{re_home}`, `{build_box}` and `{ans:*}` literal, so the output does not depend on the machine and holds no home path.
  - Sections: "One-time setup" / "Each run, in this order" / "What to check (pass = done)" (`- [ ]`) / "If it fails".
  - Roles render as **You:**/**Script:**. cmds render as fenced `shlex.join`.
- pending:
  - Lists each session that has no PASS result in the state-dir, in §5 Q order, with its `q`.
  - It marks a session `ready` when every session in its `after` has a PASS result.

**fps.py:**
- MangoHud CSV layout: a preamble `os,cpu,gpu,...`, then a values line, then the column header whose first cell is `fps` (`frametime` is in ms).
- p50 = median fps. p1 = `1000/pct(frametime,99)` when `frametime` exists, else `pct(fps,1)` (nearest rank).
- pass = `p50 >= --min`.
- No header or no rows → exit 2.

**disparity.py:**
- Decoders:
  - PNG: signature, IHDR/PLTE/IDAT/IEND, `zlib.decompress`, unfilter types 0-4. Colour types 0/2/3/4/6 at depth 8; depth 16 keeps the high byte. Interlace 1 → exit 2.
  - PPM/PGM: P5/P6, maxval ≤255, `#` comments.
- Luma = `(299R+587G+114B)//1000`. Split by layout: sbs = left/right halves, tab = top/bottom halves. Disparity is horizontal in both.
- Blocks are `block`² on a `step` grid, skipping a `max_shift` border. A block counts when its std-dev ≥ `min-texture`.
- For each block, `d` = the SAD argmin over ±`max_shift`; keep `|d|`.
- Reports `n`, `mean`, `p90`. pass = `n>0 and mean > --min` (">1 px", T12).

**Tests:**
- `tools/session/test_session.py`:
  - `check` passes on every repo `sessions/*.toml`. Repo root is `Path(__file__).parents[2]`.
  - `check` rejects:
    - a duplicate id
    - an unknown kind
    - an unknown placeholder
    - `name`≠stem
    - a cmd without `run`
    - a literal home path, built as `"/home/" + "x"`
    - an `evidence_only` issue that is not in `issues`
    - an `evidence_only` session without `vars.appid`
    - a missing or unknown `q` (`"Q17"`)
    - a glob in `run` (`["ls", "{state}/soak-*.txt"]`), while `["find", "{state}", "-name", "soak-*.txt"]` passes
  - render is deterministic and contains every step text plus the generated header. Its output for every repo session contains no `/home/` and keeps `{home}` and `{state}` literal.
  - `run --script` on a temp TOML:
    - cmds `python3 -c "print('ok')"` (expect `ok`) and `false` (optional) → PASS;
    - check `n` → FAIL; `s` → INCOMPLETE; `s` on an optional step → still PASS;
    - a `who=you` cmd is not run, and its answer sets its status;
    - the JSON and .md land in a temp `--state-dir`, named `<name>-<now>.json`. The JSON has `q`, `commit`, `dirty` and a `who` on each step. The .md has `## Verified` and `## Not verified`;
    - a cmd printing `{"ok":true,"command":"x","data":{"ok":false}}` fails `expect_json = {"/data/ok" = true}`;
    - a cmd printing an error envelope with code `link-not-ready` passes `expect_code = "link-not-ready"` and records `code`;
    - a measure with a synthetic CSV records p50;
    - an optional measure with no input file → still PASS;
    - an `evidence_only=[36]` session's .md contains "Evidence for #36" and has no match for `(?i)\b(close[sd]?|fix(e[sd])?|resolve[sd]?)\s+#36\b`.
  - A missing answer → exit 2, and stderr names the step id.
  - Dry run: every repo session `run --dry-run` exits 0 with `PATH` set to a temp dir of stand-in executables, one per name in a fixed list in the test. A bare-name `run[0]` outside that list fails the test. The state-dir stays empty.
  - pending: with a PASS result for `q0` in a temp state-dir, `q0` is not listed and `g1-geo11` is marked ready.
  - Commands table: every `flat3d-inject <word>` argv in the repo sessions has `<word>` in column 1 of `docs/code-map.md`'s `## Commands` table. The test skips with a notice while that heading is absent (WP-25b adds it).
- `tools/stereo/test_stereo.py`:
  - CSV with median 60 → pass; median 25 → fail (exit 1); no `fps` header → exit 2; p1 computed from frametime.
  - A PNG built in the test: chunk CRC via `zlib.crc32`, rows cycling filters 0-4, RGB and gray.
    - Random texture (`random.Random(1)`); right eye = left shifted 4 px → mean ≈4, pass.
    - Identical halves → mean 0, exit 1.
  - A PPM round-trip gives the same luma as the PNG.
  - An interlaced or truncated PNG → exit 2.
