### WP-26: Recipe seeds + repo recipe lint

**Files:** the 5 seeds `crates/engine/tests/fixtures/recipe-seeds/{2075800-star-wars-zero-company,502500-ace-combat-7,1608230-planet-of-lana,870780-control,2651280-spider-man-2}.recipe`, plus `crates/engine/tests/recipes_repo.rs` and `crates/engine/tests/recipe_seeds.rs`.

**Signatures used.** Paths are `crates/engine/src/{recipes,injectors}.rs` after the WP-01 move. The line numbers are the base `inject/src` lines, for reference only; WP-00's rustfmt may shift them, so match by content.
- `recipes::load_recipes(&Path)->Result<BTreeMap<u32,Recipe>,RecipeError>` (recipes.rs:199). It reads every `*.recipe` file in the folder and skips other files. A name with no leading `<appid>-` is a `BadFileName` error. Each file is parsed and checked.
- `recipes::parse_recipe(appid,&str)` (:113):
  - ignores keys outside `KEYS` (:127-129), so route keys can sit in the same file;
  - strips one pair of surrounding double quotes from each value (:137-140).
- `recipes::STATUSES` (:9): `works-now likely build not-safe wont-work untested`.
- `injectors::route_of(&str)->Route{Uevr,Geo11,Port,NoRoute}` (injectors.rs:20). "build…" → Port, "uevr" → Uevr, "geo-11" → Geo11.
- `injectors::check_injectable(&Recipe)->Result<(),String>` (:35): checks safe, then works-now ("is not works-now"), then route.
- Frozen by WP-01 (§2): `recipes::route_settings(text:&str)->RouteSettings` and `recipes::check_route_settings(route:&str, m:&RouteSettings)->Result<(),String>`, with `RouteSettings = BTreeMap<String,String>`. `route` is the raw `stereo-route` text, so the tests pass `&recipe.route`. `uevr-profile` and `geo11-fix` each take a pin key (`[a-z0-9-]+`), not a url and sha256.
- From WP-13 (`flat3d_inject::injectors::fetch`): `PINS` (the `packaging/pins` text, built in with `include_str!`), `parse_pins(&str)->BTreeMap<String,Pin>`, `pin_in(&BTreeMap<String,Pin>, key)->Result<Pin,FetchError>`, and `FetchError::{UnknownKey, TbdAtPin, Manual, BadPin}`. These tests use them and copy no pins parser of their own.

**Shared helpers (test-local, duplicated in both test files, ~15 lines):**
- Root is `Path::new(env!("CARGO_MANIFEST_DIR")).join("../..")`. The seeds folder is `Path::new(env!("CARGO_MANIFEST_DIR")).join("tests/fixtures/recipe-seeds")`.
- Seeds and repo recipes load with `load_recipes(folder)`. Each file's text is read with `std::fs::read_to_string` for `route_settings`.
- `let pins = fetch::parse_pins(fetch::PINS);`
- `fn pin_refs(route:Route, m:&RouteSettings)->Vec<String>`:
  - Uevr ⇒ `uevr`, plus `m.get("uevr-profile")` when present;
  - Geo11 ⇒ `geo11`, plus `m.get("geo11-fix")` when present;
  - Port and NoRoute ⇒ none.
  - It uses `get`, never `m[...]`: indexing panics on an absent key, and the 2075800 seed has no `uevr-profile`.
- `fn missing_pins(refs:&[String], pins:&BTreeMap<String,Pin>)->Vec<String>` returns the refs for which `pin_in` gives `UnknownKey`.
- Every assert message names the file, the key, and the fix (see each test below).

**Tests:**
- `recipe_seeds.rs`:
  1. `the_seeds_are_the_five_games`: `load_recipes(seeds)` is Ok, and its key set is exactly {502500, 870780, 1608230, 2075800, 2651280}.
  2. `no_seed_is_works_now`: status is `untested`, and `check_injectable` gives an Err containing "is not works-now".
  3. `each_seed_names_its_route`: 2075800/502500 → Uevr, 1608230/870780 → Geo11, 2651280 → Port.
  4. `route_keys_pass_the_frozen_check`: `check_route_settings(&r.route, &route_settings(&text))` is Ok for each file. On failure the message is `<file>: <the check's error>; fix the route key in the seed`.
  5. `pin_refs_name_real_pins`: the union of refs is exactly {uevr, ac7-profile, geo11, lana-fix, control-fix}. `missing_pins` is empty, and `pin_in` gives Ok or `TbdAtPin` for each ref (never `Manual` or `BadPin`). Seeds are untested, so a TBD sha is fine here. On failure: `<file>: <setting> names pin <key>, which packaging/pins does not hold as a fetch: auto key; fix the key or add the pin (WP-02)`.
  6. `an_unknown_pin_is_refused`: route Uevr, `m = route_settings("uevr-exe: X\nuevr-profile: no-such-pin")`, the real pins ⇒ `missing_pins(&pin_refs(Route::Uevr,&m), &pins) == ["no-such-pin"]`.
  7. `seeds_stay_out_of_recipes_until_works_now`: any `recipes/<seed appid>-*.recipe` must be works-now. On failure: `recipes/<file>: stereo-status is <status>, not works-now; keep it in crates/engine/tests/fixtures/recipe-seeds/ until a session passes`.
- `recipes_repo.rs`:
  1. `every_repo_recipe_loads`: `load_recipes(root/recipes)` is Ok. Zero entries is fine today. On failure the message is the `RecipeError` text, which names the file.
  2. `file_names_are_appid_slug`: each `*.recipe` name is `<appid>-<slug>.recipe`. Check it by hand; the engine has no regex crate and Cargo.lock is frozen after WP-01. Strip `.recipe`, then `split_once('-')`. The left side is non-empty and all ASCII digits. The right side is non-empty and only `[a-z0-9-]`. On failure: `recipes/<file>: name must be <appid>-<slug>.recipe (slug is a-z, 0-9, -); rename it`.
  3. `works_now_recipes_are_injectable`: for each works-now recipe, `check_injectable` is Ok, `check_route_settings` is Ok, `missing_pins` is empty, and `pin_in` is Ok for every ref. So a works-now recipe is refused while any pin it names is still TBD-at-pin. On a TBD pin the message is `recipes/<file>: <setting> pin <key> is TBD-at-pin; run packaging/pin.sh <key>` (the `TbdAtPin` fix text from WP-13). A `check_injectable` or `check_route_settings` failure prints `recipes/<file>: <the check's error>`. A missing pin uses the test 5 message with `recipes/<file>`. This is the gate on the later works-now recipe PRs that close #29/#36/#47-#49 (WP-24 sessions only gather evidence for them).
