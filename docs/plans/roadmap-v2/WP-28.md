```rust
// face/link_model.rs
pub fn link_view(snap: Option<LinkSnapshot>, now: u64) -> api::LinkView;
// cli/view.rs
pub fn parse(args: &[String]) -> Option<Result<ViewCommand, String>>; // None = not a view verb

// ViewCommand{View, Rows{filter:String}, Launch{add:bool, options:String},
//             Collection{current:Option<Vec<u32>>}, Toasts{last_seq:u64}, Logs{limit:usize}}
```
- The helpers `rows`, `launch`, `collection`, `toasts` and `logs` are private fns in `cli/view.rs` (§2: "Helpers stay private"). There is no `LaunchOp`; the frozen form is `Launch{add, options}`.
- `p` below is `ctx.paths`. `now` is `sys::unix_now()` at the call site; `Ctx` has no `now`.
- `api::ApiError` has no `From<String>`. Map a `String` error with `ApiError::new("io", &e)`.

**Behaviour:**
- **`view`:** `link_view(state::read_snapshot(p).map_err(|e| ApiError::new("io", &e))?, now)`.
  - `link_view`: `None` → `LinkSnapshot::stopped(now)`, else `.effective(now)` (stale after `state::STALE_SECS=10`).
  - `label` and `hint` come from `link_view::{link_label, link_hint}`; `start` and `stop` from `headset_view::headset_buttons(state)`.
  - `health` = `view::health_view(s.health.as_ref())`.
  - `rx` and `tx` = `view::throughput_text(stats.rx_bytes_s / tx_bytes_s)`; `uptime` = `view::uptime_text(stats.uptime_s)`. With no stats, all three are `"—"`.
  - `tether`, `tunnel`, `auto_3d` and `adb_source` are copied from the snapshot.
- **`rows [--filter <status>|all]`:** default `all`.
  - `games = catalog::catalog(p)?.games` (WP-07);
  - `settings = switches::read_settings(&p.settings()).map_err(|e| ApiError::new("io", &e))?`;
  - `link` = `LinkState::Stopped` when `read_snapshot` gives `None`, else `.effective(now).state`;
  - returns `rows::game_rows(&games, filter, &settings, link)` as a JSON array.
- **`launch add|remove --options <string>`:**
  - The options are exactly one argv element, the one after `--options`. It may be `""` and may contain `--` or `%command%` inside it.
  - Nothing may follow the value. A missing `--options`, a missing value, or an extra element → usage.
  - These rules apply to the argv after `cli::parse_any` (WP-01) has removed every `--json` from the head. So `--json` may sit anywhere, before or after `--options <value>`. Decky's main.py always appends a trailing `--json` (#67 locks that argv order), and it must parse.
  - Limitation: a value that is exactly `--` or exactly `--json` cannot be passed, because `parse_any` splits at the first `--` and strips `--json`.
  - `add` → `LaunchText{options: launch_options::add_wrapper_at(&options, &p.wrapper_bin().to_string_lossy())}` (WP-20). `wrapper_bin()` is a `PathBuf`, so it needs `to_string_lossy()`.
  - `remove` → `LaunchText{options: launch_options::remove_wrapper(&options)}`.
  - There is no `launch-sync` command and no `launch <appid>` form; the frozen `ViewCommand` has only `Launch{add, options}`. #121, code-map:115 and decky.md:173 all say `launch add|remove`. Decky (WP-21's `launch(verb, options)`, used by WP-32) sends `("launch", verb, "--json", "--options", cur)`, plus main.py's trailing `--json`.
- **`collection [--current <csv>]`:**
  - `--current ""` → `Some(vec![])` (WP-32 sends this on the first run). No flag → `None`. A non-number item → usage.
  - `wanted = collection::three_d_ready_appids(&catalog::catalog(p)?.games)`.
  - `add` and `remove` come from `collection::collection_diff(cur, &wanted)`, and are both empty when `None`.
  - `name = collection::COLLECTION_NAME` (`"3D Ready"`).
- **`toasts <last_seq>`:** `last_seq` is a u64; a missing value or `-1` → usage.
  - `events` = the raw snapshot's `events` (no stale check); no snapshot → `[]`.
  - Returns `serde_json::to_value(toasts::toasts_since(&events, last_seq))` (oldest first), with one extra key inserted: `"title": api::TOAST_TITLE`.
  - `ToastBatch` has no `title` field; the key is added to the JSON object only. No locked test builds a `ToastBatch` literal, and WP-21's `types.ts` mirrors it as `title?: string`.
- **`logs [--limit n]`:** follows WP-06's "Command contract: logs" and does not restate it.
  - `n ≥ 1` (`--limit 0` → usage); default `headset_view::DEFAULT_LOG_LINES` (500).
  - The body is `let lines = face::logs::read_logs(p, limit); api::LogLines{text: headset_view::log_copy_text(&lines), lines}`.
  - No local `log_lines(text, limit)` and no `read_log_text`.
- **Effects (as declared in WP-01's `cli::COMMANDS`, ruling D2):** every view verb is `ReadOnly`. `view` and `toasts` read the snapshot; `rows` and `collection` read the catalog, settings and snapshot; `logs` reads the log files and run records; `launch` is pure. No verb writes a file or sends argv to `ctx.runner` or `ctx.relay`. `launch` returns text and never writes `localconfig.vdf`.
- **Errors and output:**
  - Every command returns a JSON value. Bad args → code `usage`, exit 2 (§2 exit contract). The usage message is the view usage text, so it shows the form to type. That text is a private const in `cli/view.rs`; the locked `cli::USAGE` is unchanged.
  - Catalog and snapshot errors keep their codes (`io`, `bad-recipe`) and messages from WP-07 and WP-01. The codes stay the closed 8 in `ERROR_CODES` (ruling D6); WP-28 adds none. Fix text comes from `api::error_help` (WP-01, ruling D2); WP-28 adds none.
