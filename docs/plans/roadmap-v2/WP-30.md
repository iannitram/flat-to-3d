**Behaviour:**
- **T5 `analyze.sh` (all modes):**
  - it runs from the repo root (it `cd`s there from its own path), so the relative paths below work from any cwd;
  - each slug comes from `python3 tools/re/exe_id.py <exe>` (first field of its output). When `FLAT3D_EXE_ID` is set, analyze.sh runs `$FLAT3D_EXE_ID <exe>` instead (a path to an executable that prints `<slug> <sha> <ver>`);
  - each program name is the exe's basename. An import stores the program at `/<slug>/<basename>` in project `spiderman`;
  - the Ghidra command is `${FLAT3D_HEADLESS:-tools/ghidra/headless.sh}`. The seam exists for tests;
  - analyze.sh passes the environment to headless.sh unchanged. headless.sh (WP-25b) reads `FLAT3D_RE_HOME` and `FLAT3D_HEAVY_LOCK`; analyze.sh reads no Ghidra or JDK paths itself. Any default line naming the build box also contains `FLAT3D_BUILD_BOX`, so the private-words allow line (WP-25a) covers it;
  - `--dry-run` prints each argv, one per line, and exits 0. It never checks that a file exists;
  - honours exit 75 (busy) and 137 (low memory) from headless.sh unchanged, and stops the chain there.
- **T5 `analyze.sh analyze`:**
  - runs `headless.sh <projdir> spiderman/<slug> -import <exe> -max-cpu 16 -log <projdir>/logs/analyze-<slug>.log`;
  - the folder goes in the project-name argument, never `-folderPath`.
- **T5 `analyze.sh vt`:**
  - runs `headless.sh <projdir> spiderman/<dst-slug> -process <dst-basename> -preScript Flat3dVtOptions.java -postScript AutoVersionTrackingScript.java / <session> /<src-slug>/<src-basename> -postScript ExportVtMatches.java /<session> <out.csv> -scriptPath tools/ghidra`;
  - the third AutoVT argument is a project file path (AutoVersionTrackingScript.java:129, `defineProjectFile`), so it names the source program by folder and basename;
  - no `-readOnly`;
  - the session name is fresh, `vt-$(date +%s)`, because AutoVT refuses an existing session (AutoVersionTrackingScript.java:141-146);
  - both programs must be analysed first.
- **T8 `analyze.sh all`:** analyze src, analyze dst, vt, then `python3 tools/re/fill_map.py --map games/spiderman2/map.toml --vt <out.csv> --targets tools/xmatch/targets.py --doc docs/spiderman2/address-map.md`.
- **T7 `exe_id.py`:**
  - stdlib only;
  - streams sha256, and reads the PE version resource with the VS_FIXEDFILEINFO scan of `file_version` (tools/research/inspect_game.py:24);
  - `KNOWN_BUILDS = {sha: (slug, version)}`, built from tools/research/inspect_game.py:12-21: `e297d4…81ad1` → `('remastered-4.630', '4.630.0.0')` and `c9b912…b738c9` → `('sm2-2.810', '2.810.0.0')`. Each inspect_game description is kept as a comment;
  - `identify` returns `(slug, sha, pe_version)`, with `'-'` for the version when the file has no version resource (or is not a PE);
  - an unknown hash prints `exe_id: unknown <sha>; fix: add it to KNOWN_BUILDS in tools/re/exe_id.py` to stderr and exits 3.
- **Flat3dVtOptions.java:**
  - copies SetAutoVersionTrackingOptionsScript, using a `GhidraValuesMap` and `VTOptionDefines.*_OPTION_TEXT`;
  - ends with `state.addEnvironmentVar("autoVTOptionsMap", map)` (read at AutoVersionTrackingScript.java:207-208);
  - values:
    - CREATE_IMPLIED_MATCHES true;
    - RUN_EXACT_SYMBOL, RUN_EXACT_DATA, RUN_EXACT_FUNCTION_BYTES, RUN_EXACT_FUNCTION_INST, RUN_DUPE_FUNCTION and RUN_REF_CORRELATORS all true;
    - DATA_CORRELATOR_MIN_LEN 5, SYMBOL_CORRELATOR_MIN_LEN 3, FUNCTION_CORRELATOR_MIN_LEN 10, DUPE_FUNCTION_CORRELATOR_MIN_LEN 10;
    - APPLY_IMPLIED_MATCHES true, MIN_VOTES 2, MAX_CONFLICTS 0;
    - REF_CORRELATOR_MIN_SCORE 0.95d, REF_CORRELATOR_MIN_CONF 10.0d.
- **ExportVtMatches.java:**
  - extends `GhidraScript`;
  - `args[0]` = session path, `args[1]` = csv;
  - opens with `getProjectData().getFile(path).getDomainObject(this,true,true,monitor)`;
  - iterates `getMatchSets()` → `getMatches()`;
  - writes the header `src_rva,dst_rva,status,similarity,confidence,correlator`. Ghidra addresses are VAs (image base 0x140000000), so each RVA is `addr.subtract(program.getImageBase())` for its own program, written in hex with `0x`;
  - releases the session in `finally`. Never call `saveVersionTrackingSession`: its null check is inverted and it throws.
- **map.toml schema:**
  - `[meta] herovr_rev = "82f3ffe4e4dc65d9f0df3b29918af2ccb7fc9859"`;
  - one `[[item]]` per targets.py row (85): `name`, `rem_rva` (hex string), `kind`, `prio`, `sm2` (`""` or hex), `sig`, `conf`, `how`, `status` (`pending|found`). A found item also has `similarity`, `confidence`, `correlator` and `verified_by`;
  - `verified_by` is the receipt for the match: `"<csv basename> sha256:<first 12 hex of the csv's sha256>"`, written by fill_map when the VT row lands;
  - one `[[herovr]]` per HEROVR item H1-H11: `id`, `what` (prose, no hex), `check`, `item` (our item name or `""`), `evidence` (our tool name). `check` ∈ `found|not-found|pending|runtime|off-path|no-row`;
  - seed: every item from targets.py with `status = "pending"`. HEROVR rows: H1 runtime; H2-H5 and H7-H10 pending; H6 no-row; H11 off-path. The `what` text comes from HEROVR's BUILD-SM2.md at `herovr_rev`, read once with `gh api 'repos/lecutis7of9/HEROVR/contents/BUILD-SM2.md?ref=82f3ffe4e4dc65d9f0df3b29918af2ccb7fc9859' -H 'Accept: application/vnd.github.raw'`. That is a read-only `gh` read, which §0 already allows any WP; WP-30 needs no other network.
- **T6 `fill_map.py` (render):**
  - stdlib only, Python 3.12+ (`tomllib` to read; it emits TOML itself, because there is no writer);
  - loads targets.py with `importlib.util.spec_from_file_location`, with no `sys.path` edits;
  - `--vt` is optional. Without it every item stays as map.toml says, so `--check` runs with no VT csv (check.sh step 14, WP-02);
  - merges VT rows into `map.toml` by Remastered RVA. `load_vt` keeps, per source RVA, the row with the highest similarity, then confidence, then the first seen;
  - a target becomes `found` only when a VT match is computed for it. Then fill_map sets `sm2` (the dst RVA), `similarity`, `confidence`, `correlator`, `verified_by` and `status = "found"`;
  - `render_table` uses the header and separator of tools/xmatch/mkmap.py:14-15 verbatim;
  - `render_block` runs `render_table(p, ...)` for p = 1, 2, 3, each under its `### Priority N. <pn[N]>` heading from mkmap.py:10-11, with the blank lines mkmap prints around each heading. The block starts at the first heading line, with no leading blank line. After the prio tables it renders a `### Checked against HEROVR's list` table with columns `| HEROVR item | Our row | Check | Evidence |`, one row per `[[herovr]]`;
  - `splice` replaces only the text between the two literal lines `<!-- BEGIN GENERATED -->` and `<!-- END GENERATED -->`, one block for all three prio sections plus the HEROVR table. WP-25b places BEGIN just before `### Priority 1` (:62) and END just after the last Priority 3 row (:160), before `## Next leg` (:162). With no HEROVR rows, the block's prio part equals today's :62-:160 byte for byte (mkmap output matches it);
  - missing or duplicated markers → exit 2 with `fill_map: <doc>: needs exactly one <!-- BEGIN GENERATED --> / <!-- END GENERATED --> pair; fix: restore the marker lines (WP-25b placement)` (no guessing);
  - `--check` writes nothing. It exits 1 on drift and prints `fix: python3 tools/re/fill_map.py --map games/spiderman2/map.toml --targets tools/xmatch/targets.py --doc docs/spiderman2/address-map.md`.
- **Lints (exit 1, each line names the row and the fix):**
  - an `evidence` field equal to `herovr`;
  - any `[0-9a-fA-F]{5,}` inside `[[herovr]]` text;
  - `found` without `similarity`, `confidence` and `correlator` (a computed match);
  - `found` without `verified_by`.
- **One owner per fact:** `games/spiderman2/map.toml` holds the addresses. The doc block is generated from it. WP-25a's `check.py` `generated` rule checks only that the doc has one ordered marker pair; it does not regenerate or compare the block. Drift is caught by `fill_map.py --check`, which WP-02's check.sh runs (step 14) once fill_map.py exists.
