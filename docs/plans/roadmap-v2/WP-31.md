**Behaviour**
- **`run_with`:**
  - appid comes from the private `appid()` (:98).
  - snapshot: `state::read_snapshot(paths)`, with an Err mapped to `"snapshot: {e}"`.
  - settings: `switches::read_settings(&paths.settings())`. NotFound gives Default (K5). Any other Err is mapped to `"settings: {e}"`.
  - recipe: `catalog::find_recipe(&paths.recipe_dirs, id)` (`{id}.recipe` or `{id}-*.recipe`, first dir wins; this fixes A5) gives `(path, text)`. Then `recipes::parse_recipe` and `check_recipe`. Any Err is mapped to `"recipe: {e}"`. `Ok(None)` is no recipe.
  - Then `prepare_with_route` with a closure that captures `paths`, `runner` and the recipe `text`. Its body:
    1. `game`: `steam::installed_games(&paths.home.join(steam::DEFAULT_STEAM_ROOT))`, then the entry with `appid == id`. Not found, or an IO error, gives `Err("route: game {id} is not installed")`.
    2. `settings = recipes::route_settings(&text)`, then `recipes::check_route_settings(&r.route, &settings).map_err(|e| format!("route: {e}"))?`.
    3. `env = injectors::ensure_applied(&game, r, &settings, paths, &mut *runner).map_err(|e| format!("route: {e}"))?`.
    4. `dirs = wivrn::detect_server(&mut *runner).map_err(|e| format!("wivrn: {e}"))?`.
    5. `Ok((env, dirs))`.
- **`prepare_with_route` order:**
  - appid error, then `Ok(None)` snapshot ("no link snapshot"), then `state::is_stale(s.updated,now)` ("snapshot is stale").
  - Then `plan(s.state, settings.game_on(id), recipe)`. The gate stays `link == LinkState::Ready` inside `plan` (:270). OD4 is unchanged: grace is not special-cased here, so a launch in grace plays flat.
  - Only when the plan is `ThreeD`: require a non-empty HOME ("HOME is missing"), then call `route` exactly once.
  - Any `Err(m)` gives `Plan::Flat{NotInjectable(m)}` and the message `"flat: {m}"`. On a Flat plan, `route` is never called and the runner sees no argv.
  - **Inherited `WINEDLLOVERRIDES` (questions.md 61: merge, the route wins).** When the `RouteEnv` that `route` returned has a `WINEDLLOVERRIDES` entry with value `R`, and the `env` argument holds a non-empty `WINEDLLOVERRIDES` value `I` (set by the user's Steam launch options), replace that entry's value before `exec_spec_with` is called. Split `I` on `;`. In each piece, the dll names are the comma list before `=` (the whole piece when it has no `=`). Remove the names that `R` also names, and drop a piece that has no name left. Then append `R` unchanged and join everything with `;`. Example: `I = dinput8=n,b;d3d11=b` and `R = d3d11,nvapi64=n,b` give `dinput8=n,b;d3d11,nvapi64=n,b`. With no inherited value, or no route entry, nothing changes. The helper is a private fn in wrapper.rs.
  - `Launch.command = exec_spec_with(..)`. The message formats match legacy: `"3d: {route:?}"` and `"flat: {reason.text()}"`.
- **`exec_spec_with`:**
  - Flat: `argv` only, empty env and unset, `sidecar: None`.
  - ThreeD: the same 3 PV vars as :237-247, but the WiVRn folder is `wivrn.app_dir.to_string_lossy()`, so a system install gives `/var/lib/flatpak/app/io.github.wivrn.wivrn`. FS_RW merging is the same as :230-236.
  - Then `route.env`. A key already present is replaced in place, so there is one entry per key and the last value wins.
  - `unset = route.unset` minus any key that is also in env, deduped.
  - `sidecar = route.sidecar.clone()`, verbatim. The bin appends `--until-pid`.
- **Reason codes:** a flat launch has one code from `FLAT_REASONS`. The private `reason_code(message)` reads the text after `flat: `:
  - `missing or invalid Steam appid` → `appid`; `snapshot is stale` → `stale`; `no link snapshot` or `snapshot: …` → `snapshot`; `settings: …` → `settings`; `recipe: …` → `recipe`;
  - `no recipe` → `no-recipe`; `3D switch is off` → `switch-off`; `headset link is not ready` → `link-not-ready`; `HOME is missing` → `home`;
  - `route: …` → `route`; `wivrn: …` → `wivrn`; `sidecar: …` → `sidecar`;
  - anything else (a `check_injectable` message) → `not-injectable`.
- **Record:** `record_text(launch)` is `record.to_text()`. When `record.mode` is Flat it adds `reason\t<code>` and `note\t<message>`, with `\n` and `\r` in the message replaced by spaces. Extra lines are legal (runs_extra_lines.rs).
  - It is written atomically: `std::fs::create_dir_all(state::runs_dir(&paths.state_dir.to_string_lossy()))`, then `fsx::write_atomic` to `state::run_record_path(&paths.state_dir.to_string_lossy(), pid)`.
  - Then `fsx::append_line(paths.run_log(), "{now} appid={} pid={pid} {msg}")`, with newlines replaced as at :172.
  - IO failures append `; run record: {e}`. The launcher is always called exactly once (same guarantee as :117-118).
  - When the launcher returns Err, append the legacy `exec: {e}` run.log line (:177-179).
- **`sidecar_argv`:** an empty `sc` gives `Err("sidecar: empty argv")`. An absolute `sc[0]` is used as is. Otherwise the program is `exe_dir/sc[0]` when `exists` says it is there, else `bin/sc[0]`. The result is that program, then `sc[1..]`, then `--until-pid <until_pid>`.
- **`flat3d-run.rs`:**
  - `env` is today's map from `vars_os` (non-UTF-8 pairs dropped). `EnginePaths::from_env(&env, sys::current_uid())` (§2 form). On Err, exec argv untouched with an empty env and unset, write no record, and print `flat3d-run: paths: {e.code}: {e.message}` to stderr. Delete the local `uid()` (:7-19) in favour of `sys::current_uid`.
  - Runner: `exec::SystemRunner`.
  - Launcher: if `command.sidecar` is `Some(sc)`, build the argv with `sidecar_argv(&sc, current_exe().parent(), &paths.bin, std::process::id(), &|p| p.exists())`. Spawn it with stdin null and stdout/stderr appended to `paths.log_dir/viewer.log`.
    - On Ok: `note_run(.., "sidecar", "pid {id} {argv}")`.
    - On Err (from `sidecar_argv` or the spawn): `flat_after_sidecar_error`, which rewrites the record to `mode flat` with `reason\tsidecar` and `note\tsidecar: {e}`, and logs `flat: sidecar: {e}`. Then exec the flat spec.
  - Then `Command::new(argv[0]).args(..).envs(env)`, plus `env_remove(k)` for each `unset`, then `exec()` (unix), as at :53-66.
  - The viewer exits when the game pid exits (WP-19 strips `--until-pid`), so it is re-parented and reaped and leaves no zombie.
  - The bin's `Command::new` stays on the `tests/architecture.rs` allowlist (§2). wrapper.rs spawns nothing, which is why `sidecar_argv` is pure.
