**Behaviour**
- **Engine calls go through the named wrappers only.** Every call uses a WP-21 `engine.ts` wrapper (`view`, `rows`, `start3d`, `stop3d`, `setSwitch`, `setSetting`, `launch`, `doctor`, `collection`, `toasts`), never a raw `engine("word", ...)`. WP-28's `decky_face.rs` parses each wrapper's argv through `cli::parse_any` against the `cli::COMMANDS` registry (A5, D2), so a call that bypasses the wrappers is untested. If WP-32 needs a call no wrapper covers, that is a WP-21 follow-up, not a raw call here.
- **Errors keep their code.** On any `!ok` envelope, show one `Field label={error.code} description={error.message}`, both verbatim. There is no wording of our own and no logic: the engine owns the message, and where one command fixes the error the message names it.
- **`panel.tsx`:**
  - While mounted, a 1 s `setInterval` calls `view()` and `rows()`. Clear it on unmount.
  - On mount, in a `useEffect`, run `syncCollection().then(p => p && syncLaunchOptions(p))`, and show each returned `ApiError` as a `Field`, as above.
  - Render order (#131):
    1. `Field label={v.label} description={v.hint}`.
    2. `ButtonItem` "Start 3D" (`disabled={!v.start}`) calls `start3d()`. "Stop 3D" (`!v.stop`) calls `stop3d()`. Both are requests; the CLI follows the A24 one-actor rule.
    3. Health: `v.health.battery`, `v.health.temp` (colour `v.health.colour`), `v.rx`/`v.tx`/`v.uptime`.
    4. Toggles: `ToggleField` "Tunnel" (`checked={v.tunnel}`) calls `setSetting("tunnel", on)`. "Auto 3D" (`checked={v.auto_3d}`) calls `setSetting("auto-3d", on)`.
    5. One `ToggleField` per row (`label=r.name`, `description=r.flat_reason ?? r.status_label`, `checked=r.switch_on`). It calls `setSwitch(r.appid, on)`, then refreshes.
    6. A "Check setup" `ButtonItem` calls `doctor()` on demand only (it runs adb). It lists the checks where `!ok` as `Field label={name} description={detail+" — "+fix}`.
  - A red doctor report exits 1 but still prints the full report in an `ok:true` envelope (D4, §2 `cli::ok_exit`), and WP-21's `main.py` returns any envelope with a bool `ok` unchanged, whatever the exit code. So the panel reads `data.checks` on `ok:true` whether `data.ok` is true or false. Only an `ok:false` envelope is an error.
- **`collection.ts`:**
  - A module-level `let name = "3D Ready"` (collection.rs:8, `COLLECTION_NAME`).
  - `const id = collectionStore.GetCollectionIDByUserTag(name)`.
  - `const c = (id ? collectionStore.GetCollection(id) : null) ?? collectionStore.NewUnsavedCollection(name, undefined as unknown as Parameters<typeof collectionStore.NewUnsavedCollection>[1], [])`. The cast is needed because the filter param's type rejects `undefined`. There is no `any`.
  - `r = await collection(Array.from(c.apps.keys()))`. Always pass an array, even an empty one: the wrapper then sends `--current ""`, which WP-28 parses as `Some([])`, so `add` equals `wanted` on the first run. Passing nothing sends no `--current`, and `add` and `remove` come back empty.
  - If `!r.ok`, return `null`. Otherwise set `name = r.data.name`, which later runs use for the lookup.
  - `ov = ids => ids.map(i => appStore.GetAppOverviewByAppID(i)).filter((o): o is NonNullable<typeof o> => !!o)`.
  - Call `c.AddApps(ov(r.data.add))` and `c.RemoveApps(ov(r.data.remove))` on the `CCollection` itself, then `await c.Save()`, only when `add.length + remove.length > 0`. Return `r.data`.
  - Do not use `AsDragDropCollection()`: it returns `CCollectionBase | null`, which has no `AddApps`, `RemoveApps` or `Save`.
- **`launch.ts`:**
  - There is no `launch-sync` command. The frozen `ViewCommand` has only `Launch{add, options}` (§2), so launch sync is one `launch` call per app.
  - For `id` of `plan.wanted`: `await appDetailsStore.RequestAppDetails(id)`, then `cur = appDetailsStore.GetAppDetails(id)?.strLaunchOptions ?? ""`, then `r = await launch("add", cur)`. The wrapper sends `["launch","add","--json","--options",cur]`.
  - If `r.ok && r.data.options !== cur`, call `SteamClient.Apps.SetAppLaunchOptions(id, r.data.options)`. It is fire-and-forget (void).
  - For `id` of `plan.remove`, do the same with `launch("remove", cur)`.
  - Each `!r.ok` adds `r.error` to the returned list. Nothing is dropped.
  - `cur` goes in as one argv element. The engine does all the parsing, adds our absolute-path word, and strips the bare or absolute word without touching the rest (OD5: no saved line is ever restored).
- **`toasts.ts`:** `lastSeq = 0` in memory. Every 2 s, `b = await toasts(lastSeq)`. If `b.ok`, call `toaster.toast({ title: TOAST_TITLE, body: t.text })` for each toast (oldest first), then `lastSeq = b.data.last_seq`.
- **`index.tsx`:**
  - Inside `definePlugin`, call `stop = startToasts()`. The interval lives outside the QAM (decky.md:44).
  - Then `void syncCollection().then(p => p && syncLaunchOptions(p))` once at load. Its errors are not shown at load; the panel's mount sync shows them.
  - `titleView = <div className={staticClasses.Title}>Flat to 3D</div>`, icon `FaVrCardboard` from `react-icons/fa`.
