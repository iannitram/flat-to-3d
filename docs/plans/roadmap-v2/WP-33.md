**Behaviour**
- **`update` routing:**
  - `Select(t)` sets `active` and returns `[ReadSnapshot]`, plus `LoadRows{filter: games.filter.clone()}` for Games, `ReadPackages` for Setup, and `LoadLogs` for Logs.
  - `Tick(n)` sets `now=n`, then `ticks+=1`, and returns `[ReadSnapshot]`. Add `LoadLogs` when Logs is active, and `ReadPackages` when Setup is active and `ticks%10==0` (checked after the increment, so ticks 10, 20, …).
  - `Headset(m)` → `headset_page::update`: `Start3d`/`Stop3d` → `Request(Request::Start3d|Stop3d)`, `SetSetting{key,on}` → `SetSetting{key,on}`, `Refresh` → `ReadSnapshot`.
  - `Games(m)` → `games_page::update`: `LoadRows`, `SetSwitch` and `Undo` map 1:1.
  - `Logs(m)` → `logs_page::update`: `Load` → `LoadLogs`, `Copy(t)` → `Copy(t)`.
  - `Setup(m)` → `setup_page::update(&mut app.setup, m)`: `RunSetup(k)` → `RunSetup(k)`, `Refresh` → `ReadPackages`. Results (`Packages(..)`, `Done(..)`) come back through the same `update` and land in `SetupState`. `lib.rs` keeps no setup state of its own.
  - `SwitchSaved(Ok)` → `[LoadRows{filter: games.filter.clone()}]`. `SwitchSaved(Err(e))` sets `games.error=Some(e)` and returns `[]`.
- **`main.rs`:**
  - `iced::application(App::default, step, view).title("Flat to 3D").subscription(|_| iced::time::every(Duration::from_secs(1)).map(|_| Message::Tick(flat3d_inject::sys::unix_now()))).run()`. The map closure captures nothing (iced hashes subscriptions by closure type).
  - `step(app,m) -> Task<Message>` = `Task::batch(update(app,m).into_iter().map(run_effect))`.
  - `Copy(t)` → `iced::clipboard::write(t)`. Every other effect → `Task::perform(engine::off_thread(move || ..), ..)`. `off_thread` sends the closure's result through `iced::futures::channel::oneshot` from a `std::thread::spawn` thread. A dropped sender gives `None`, which maps to that effect's error message `"worker stopped"`.
  - `off_thread` lives in `engine.rs`, not `main.rs`, because the app layering rule (test 18, WP-02's `app-io` step) allows `std::thread` only in `engine.rs`. `main.rs` uses no `std::fs`, `std::process`, `std::net` or `std::thread`.
  - `engine::paths()` is called inside each worker. Its `Err(e)` becomes that effect's error message, `error_text(&e)`.
  - Effects map back as follows. Each CLI effect runs `run_cli(&effect_args(&e).unwrap())`, and each `Err(e)` becomes `error_text(&e)`:
    - `ReadSnapshot` → `Headset(Msg::Snapshot(engine::read_snapshot(&p, sys::unix_now())))`;
    - `Request(r)` → `Headset(Msg::Done(engine::request(&p, r)))`. The app never runs adb or `link::start_3d`; Start/Stop only writes the request file;
    - `SetSetting{..}` → `Headset(Msg::Done(..))`, data ignored (WP-08);
    - `LoadRows{..}` → `Games(Msg::Rows(..))` (WP-28): `data` is an array, and each element goes through `row_from_json`. An element that gives `None` makes the whole result `Err("bad row: <json>")`;
    - `SetSwitch{..}` → `SwitchSaved(..)`, data ignored (WP-08);
    - `Undo(id)` → `Games(Msg::UndoDone(..))` (WP-27), `Ok(data["summary"] as string)`. The summary is `UndoResult.summary` (undo.rs:248);
    - `ReadPackages` → `Setup(Msg::Packages(..))` (WP-29). `data` is `{"wivrn":bool,"missing":[..]}`, built by hand into `Packages{wivrn}` (WP-37 drops the `gnirehtet` field) (pub fields, setup.rs:18-21; no Deserialize). A missing or non-bool key is `Err`;
    - `RunSetup(k)` → `Setup(Msg::Done(run_cli(..).map(|_| ())))`. WP-05's `Done(Ok)` returns `Refresh`, which re-reads the packages. A red doctor arrives as `Done(Err(..))` (see `run_cli_at`). The install-apps summary is not shown, because WP-05's `Done` carries `()`; only errors are;
    - `LoadLogs` → as WP-06's "Command contract: logs" (App bullet): `Logs(Msg::Lines(read_logs(&p, DEFAULT_LOG_LINES)))`, no CLI call, and `Logs(Msg::Failed(..))` when `paths()` fails.
  - `view`: the tabs are a button row as today (main.rs:13-19). Below it is the active page: Setup `view_setup::view(&app.setup, app.headset.snapshot.as_ref()).map(Message::Setup)`, Headset `view_headset::view(&app.headset, app.now).map(Message::Headset)`, Games `…map(Message::Games)`, Logs `…map(Message::Logs)`. `SetupState.snapshot` stays `None`: the Headset page's snapshot is the one source. Closing the window leaves `flat3d-link.service` running (the app starts and stops nothing).
- **`paths()`:** `EnginePaths::from_env(&std::env::vars().collect(), flat3d_inject::sys::current_uid())`, the §2 frozen form `from_env(env:&BTreeMap<String,String>, uid:u32)->Result<EnginePaths,ApiError>`, returned as is. A missing `HOME` gives `not-found`. WP-31's `flat3d-run.rs` uses the same form.
- **`effect_args`** (the face parity map, A5). It is an exhaustive `match` with no `_` arm, so a new `Effect` variant forces a decision. No argv contains `--json`.
  - `SetSetting{key,on}` → `["setting","set",key, "on"|"off"]`;
  - `LoadRows{filter}` → `["rows","--filter",filter]`;
  - `SetSwitch{appid,on}` → `["switch","set",appid, "on"|"off"]`;
  - `Undo(id)` → `["undo",id]`;
  - `ReadPackages` → `SetupKind::Packages.args()`;
  - `RunSetup(k)` → `k.args()`;
  - `ReadSnapshot`, `Request(_)`, `LoadLogs` and `Copy(_)` → `None` (no CLI call).
  - WP-04's setting keys, WP-05's `SetupKind` and WP-23's Games actions are checked here, not in those WPs.
- **`cli_path` order:** `exe.parent()/flat3d-inject`, then `<src_dir>/bin/flat3d-inject` when `src_dir` is `Some`, then `bin` (the caller passes `Path::new("bin/flat3d-inject")`). The first one where `exists(p)` is true wins, else `None`. `run_cli` calls it with `std::env::current_exe()`, `std::env::var("FLAT3D_SRC_DIR").ok().as_deref()` and `&|p| p.exists()`. `None` → `ApiError{code:"not-found", message:"flat3d-inject not found next to flat3d-app, in $FLAT3D_SRC_DIR/bin or in bin/"}`.
- **`run_cli_at`:** runs `cli` with `std::process::Command`, passing `args` and then `--json` exactly once (the callers never pass it). It passes stdout to `parse_envelope`; the engine prints the envelope on stdout for both ok and error exits.
  - An error envelope → `Err` with that envelope's `ApiError`.
  - An ok envelope with exit 0 → `Ok(data)`.
  - An ok envelope with a non-zero exit (a red doctor exits 1 and still prints the full report, D4 / `cli::ok_exit`) → `Err(ApiError{code:"command-failed", ..})`. For a `DoctorReport` the message lists each red check as `name: fix`, joined with `"; "`.
- **`parse_envelope`:** the `api::Response` shape (api.rs:110-116). `{"ok":true,"data":..}` → `Ok(data or Null)`. `{"ok":false,"error":{"code","message"}}` → `Err` with that `ApiError`, code kept (A4). Not JSON → `Err(ApiError{code:"command-failed", message:"bad engine output: <first 200 chars>"})`. The 8 codes are closed (D6), so no new code is added.
- **`error_text`:** `"<code>: <message>"`. A `usage` code renders as `"app/CLI mismatch: <message>"`, because the app built an argv the CLI did not accept.
- **`snapshot_or_stopped`:** `Ok(None)` → `Ok(LinkSnapshot::stopped(now))`. `Ok(Some(s))` → `Ok(s.effective(now))` (api.rs:233: stale after `STALE_SECS=10` counts as stopped). `Err` passes through.
- **Views:**
  - `view_headset`: `let v = link_view(s.snapshot.clone(), now);` (§2 frozen form `link_view(Option<LinkSnapshot>, now:u64)->api::LinkView`, body WP-28). It shows `v.label`, `v.hint`, the health line `v.health.battery` / `v.health.temp` coloured with `v.health.colour.parse::<Color>().unwrap_or(Color::WHITE)`. No throughput or uptime line and no Tunnel switch (removed, ruling 42). The Start/Stop buttons get `.on_press(Msg::StartPressed|StopPressed)` only when `v.start`/`v.stop` is true and `!s.busy`. Then `toggler(v.auto_3d).label("Auto 3D").on_toggle(Msg::SetAuto3d)`. A read-only Quest Tether line is added later by WP-38; this WP does not add it. `s.error` shows as text.
  - `view_games`: `pick_list(["all"] + STATUSES as Vec<String>, Some(s.filter.clone()), Msg::Filter)`. A `scrollable` column of rows: name, `text(&row.status_label).color(row.status_colour.parse::<Color>().unwrap_or(Color::WHITE))`, `toggler(row.switch_on).on_toggle(move |on| Msg::Switch{appid,on})`, `flat_reason` when `Some`, and an Undo button (`UndoPressed(appid)`). `s.note` and `s.error` show as text.
  - `view_setup`: `setup_page::steps(s.packages.as_ref(), snap)` gives one line each: `✓` or `○`, the title, and the hint when not done. Then `adb_source_text(snap)`, `s.error` as text, and three buttons: "Check again" → `RunPressed(SetupKind::Packages)`, "Install headset apps" → `RunPressed(SetupKind::InstallApps)` and "Run doctor" → `RunPressed(SetupKind::Doctor)`. Each has no `on_press` while `s.busy`. "Check again" goes through `RunPressed` so that `busy` is set and then cleared by `Done` (WP-05 clears `busy` only on `Done`).
  - `view_logs`: a `scrollable` of `logs_page::visible(s)` lines, an "All / Errors" filter (`SetFilter`), Refresh (`Refresh`) and Copy (`CopyPressed`). `s.error` shows as text.
  - iced 0.14.0 has no `Color::parse`. Colours parse through `Color`'s `FromStr` (iced_core color.rs:215).
