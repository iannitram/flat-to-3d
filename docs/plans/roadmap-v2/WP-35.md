### WP-35: Move adb choice to `link/adb.rs`

- **Wave:** 2b (after the wave-2 stack is on main, before any wave-3 branch is cut). Order: WP-35 -> WP-36 -> WP-37.
- **Closes:** nothing by issue number. Refs the new issue "Move adb choice from `tether/adb.rs` to `link/adb.rs`" (audit PR 1), which the PM opens. The code move has no device half.
- **Why:** WiVRn's wired mode needs adb (`adb reverse tcp:9757`), so choosing and running adb stays in Flat to 3D. The tether module that holds it today goes away in WP-36 (ruling 42, 2026-11-10). This WP is the safe first step: the same code in a new home, no behaviour change.
- **Files (exclusive):** `crates/engine/src/link/adb.rs` (new), `crates/engine/src/link.rs` (the `pub mod adb;` line and a re-export only), `crates/engine/src/tether/adb.rs` (keeps `TetherAdb` and the tether's own adb command lists; imports the moved items from `link::adb`), `crates/engine/src/watch/run.rs` (imports), `crates/engine/src/watch/service.rs` (imports only), `crates/engine/src/install.rs` (the `tools_dir` import only), `crates/engine/tests/architecture.rs` (the allowlist path), `crates/engine/tests/link_adb_choice.rs` and `crates/engine/tests/link_adb_runner.rs` (renamed from `tether_adb_choice.rs` and `tether_adb_runner.rs`).

**Signatures**

Moved as they are from `tether/adb.rs` to `link/adb.rs`: `listener_pid(ss_output, port)`, `proc_exe_path(pid)`, `tools_dir(home)` (`~/.local/share/flat3d/bin`), `bundled_adb(home)`, `AdbSource`/`AdbChoice { path, source }`, `choose_adb(running, bundled)`, `AdbRunner<R: link::CommandRunner>` with `new` and `inner` (it swaps the `adb` word and adds `-s <serial>` except for server commands). New and small: `pub fn run(runner, adb, serial, argv)`, a helper that replaces `TetherAdb::run` for callers outside the tether. `TetherAdb` and `reverse_list_command`, `install_command`, `remove_reverse_command` stay in `tether/adb.rs` until WP-36 deletes them. `pub use` lines keep every old path compiling inside `tether/` only.

**Behaviour:** none changes. The adb in use is still found the same way: a running server's binary (`/proc/<pid>/exe` of the listener on port 5037), else the bundled adb, else missing.
