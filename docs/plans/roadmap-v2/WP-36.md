### WP-36: Remove the tether from watch, exec, api and settings

- **Wave:** 2b, after WP-35 and before WP-37. The audit's PRs 2, 3 and 4 are three PRs of this one WP, in this order.
- **Closes:** nothing by issue number. Refs the new issue "Remove the tether from the link service (watch, exec, api, settings)". The PM closes #125 as not planned (tunnel health is Quest Tether's).
- **Why:** ruling 42 (2026-11-10): Flat to 3D and Quest Tether stay separate apps, so the built-in tether (gnirehtet relay, `tun0`, Wi-Fi move, heal ladder, step-aside, connect and disconnect plans) is deleted. Done-when: `git grep -i -E 'gnirehtet|tun0' crates/` finds nothing in `crates/engine` and CI is green. (`crates/app` and `decky/` are WP-37.)
- **Files (exclusive):**
  - PR 2, the watch service: `crates/engine/src/watch/machine.rs`, `crates/engine/src/watch/service.rs`, `crates/engine/src/watch/health_loop.rs`, `crates/engine/tests/watch_plug.rs`, `crates/engine/tests/watch_grace.rs`, `crates/engine/tests/watch_manual.rs`, `crates/engine/tests/health_loop.rs` (new, replaces `tether_health.rs`).
  - PR 3, the module: `crates/engine/src/lib.rs` (the `pub mod tether;` line), `crates/engine/src/tether.rs` and `crates/engine/src/tether/{adb,heal,plan,relay,stepaside,wifi}.rs` (deleted), `crates/engine/tests/tether_{adb_choice_gone,heal,plan,plan_run,relay_cmds,runtime,stepaside,tunnel,tunnel_review,wifi_cmds,wifi_parse,wifi_sync,health}.rs` (every `tether_*` test file still present is deleted; the two adb ones were renamed by WP-35), `crates/engine/src/exec.rs`, `crates/engine/src/testing.rs`, `crates/engine/src/cli.rs`, `crates/engine/src/stats.rs` and `crates/engine/tests/stats_{rate,soak}.rs` (deleted: throughput and soak belong to the tunnel), `crates/engine/tests/face_logs.rs` (sample strings only).
  - PR 4, the API and settings shape: `crates/engine/src/api.rs`, `crates/engine/src/switches.rs`, `crates/engine/src/wrapper.rs`, `crates/engine/src/cli/link.rs`, `crates/engine/src/face/link_model.rs`, `crates/engine/src/face/view.rs`, `crates/engine/tests/{api_snapshot,cli_link_parse,cli_link_run,cli_list,cli_view,decky_face,switches_settings,switches_io,rows,wrapper_run,view_health,link_stop_twice}.rs` (`cli_link_run`, `cli_list`, `cli_view` and `decky_face` lose the relay runner in `Ctx`, the `tunnel` key and the tether snapshot fields that WP-08 and WP-32 built), `crates/app/tests/logs_page.rs` (sample strings only).

**What is removed**
- `watch/machine.rs`: `Effect::StartTether`, `Effect::StopTether`, `Inputs.tunnel_on`, and the six arms that push them. `link_commands` is untouched.
- `watch/service.rs`: the `Shared` relay methods, the fields `tether`, `tether_serial` and `heal`, `connect_tether`, `disconnect_tether`, `tether_for`, `wivrn_by_tether`, the snapshot's `tether` and `tunnel`, the `stepaside` call; the four inline tests that assert tether behaviour are rewritten to assert the 3D link only.
- `watch/health_loop.rs`: `tick` becomes `tick(&mut self, now, playing, r: &mut dyn exec::CommandRunner) -> HealthTick` with `HealthTick { health: Option<Health>, toast: Option<(EventKind, String)> }`. It keeps the battery poll (`dumpsys battery`, every 30 s), the zones and the toast gate and so the toasts at 38 C and 42 C (ruling 32, M26). It loses the `tun0` probe, the heal ladder, throughput, the soak file, `HealthTick.{stats,tunnel,heal}` and the `mode` parameter. `tests/tether_health.rs` is deleted; `tests/health_loop.rs` tests the kept part (poll cadence, zones, one toast per colour change, no toast when not playing).
- `exec.rs`: `trait RelayRunner` loses `start_relay` and `stop_relay`, `ProcessRunner` loses its `relay: Option<Child>`; what is left is the one `Result<String,String>` runner (folded into `CommandRunner`); the error strings "Could not run tether command", "Tether command failed" and "Could not start tether relay" are reworded to "command" wording. `testing.rs`: the relay impl of `FakeRunner` goes. `cli.rs`: `Ctx.relay` goes.
- `api.rs`: `TetherMode`, `EventKind::TetherError`, `LinkSnapshot.tether`, `LinkSnapshot.tunnel`, `LinkView.tether`, `LinkView.tunnel`, `Stats` (and so `LinkSnapshot.stats`, and the rx/tx/uptime fields of `LinkView`). `ERROR_CODES` is unchanged (it has no tether code). `AdbSource` stays.
- `switches.rs`: `Settings.tunnel` and the `tunnel` line it writes. **Old settings files that still hold a `tunnel` line must load:** the parser ignores it and the next write drops it (`wrapper.rs`' settings validator also accepts and ignores the line). `cli/link.rs`: `SettingKey::Tunnel`, the word `tunnel` and its usage strings: `setting get|set` has the key `auto-3d` only.
- `face/view.rs`: `throughput_text` and `uptime_text` (tunnel stats). `face/link_model.rs`: the stub `TetherMode::Off` and `tunnel: false`.

**Tests:** every locked test that is edited or deleted here is listed in the PR body with "unlocked by ruling 42 (owner, 2026-11-10)". New tests: `switches_settings.rs` gains `a_settings_file_with_a_tunnel_line_still_loads` (the line is ignored; the rest loads; a re-write has no `tunnel` line). `watch_service.rs` (WP-09) and the WP-12 no-tether lock on the link command lists are not touched.

**Depends on:** WP-35 (and so WP-01, WP-11, WP-20). **Owner device:** Q3 (link-smoke): plug, Start 3D, Stop 3D, unplug within and past the grace, with nothing about a tunnel.

**PR:** three PRs, in order (watch, module, API and settings), each `Refs` the issue, none `Closes`. Each PR has `## Verified` and `## Not verified`.

**Do not touch:** `link.rs`, `link/wivrn.rs`, `link/adb.rs` (WP-35 owns it); `crates/app/src` and `decky/` (WP-37).
