### WP-38: Quest Tether status line, read-only

- **Wave:** 5, after the faces of wave 4 (it adds one line to files WP-28, WP-32 and WP-33 own). WP-34 runs after it.
- **Closes:** nothing by issue number. Refs the new issue "Show Quest Tether's state (read-only)".
- **Why:** ruling 42 (2026-11-10): when Quest Tether is installed, Flat to 3D may show its state, read-only. It never starts, stops or heals that link, no decision in Flat to 3D depends on the answer, and there is **no connect button**.
- **Needs first (another repo):** a written, versioned client contract in the `quest-tether` repo: the `status` fields, the `state` values (`idle`, `starting`, `connected`, `reconnecting`, `stopping`, `error`), the exit codes and a `version` field in `status`. Quest Tether's issue "Client contract: document and version the status/connect interface" delivers it. If it is not merged when this WP starts, the WP parses only `state` and tolerates every other field being absent.
- **Path note:** these paths use the new `crates/...` layout, which reaches main when the open roadmap-v2 PR stack merges.
- **Files (exclusive):** `crates/engine/src/link/quest_tether.rs` (new), `crates/engine/src/link.rs` (the `pub mod` line), `crates/engine/src/api.rs` (one optional snapshot field and one view field), `crates/engine/src/watch/service.rs` (the poll), `crates/engine/src/face/link_model.rs` (the wording), `crates/app/src/headset_page.rs`, `crates/app/src/view_headset.rs`, `decky/src/panel.tsx`, `decky/src/types.ts`, `crates/engine/tests/quest_tether_status.rs` (new), `crates/engine/tests/link_view_quest_tether.rs` (new).

**Signatures**
```rust
// link/quest_tether.rs
pub struct QuestTetherStatus { pub state: String }              // the `state` text, nothing else is acted on
pub fn status_command() -> Vec<String>;                          // ["quest-tether","status","--json"]
pub fn parse_status(out: &str) -> Option<QuestTetherStatus>;     // None for junk or a missing `state`
pub fn quest_tether_status(r: &mut dyn exec::CommandRunner) -> Option<QuestTetherStatus>; // None = not installed or no answer
// api.rs: LinkSnapshot.quest_tether: Option<String> (None = not installed), LinkView.quest_tether: String
```

**Behaviour:** `watch` runs `quest_tether_status` at most every 10 s and stores the `state` text in the snapshot; a missing binary, a non-zero exit or junk gives `None` and no event, no log line above debug. `link_view` words it: `Quest Tether: connected`, `Quest Tether: not connected` for any other state, or `Quest Tether: not installed`. Both faces draw that line and nothing else: no button, no switch, no hint to press anything. Nothing in `watch`, the wrapper or Start 3D reads the field.

**Tests:** `quest_tether_status.rs`: a sample `status --json` reply with every documented field gives `connected`; a reply with only `state` parses; `{}`, `[]`, an empty string and non-JSON give `None`; the command is exactly the three words. `link_view_quest_tether.rs`: the three wordings; the view with `None`. A third test (`nothing_depends_on_it`) runs the same watch script with `quest_tether` `None` and `connected` and asserts the same commands and events.

**Depends on:** WP-36, WP-37, WP-04, WP-21, WP-28, WP-32, WP-33. **Owner device:** Q15 (app window) and Q14 (Decky): the line reads "not installed" on a machine without Quest Tether and "connected" beside it with the tunnel up.

**PR:** `## Verified` and `## Not verified`; `Refs`, no `Closes`.

**Do not touch:** anything that starts, stops or configures Quest Tether. No `connect` or `quest-tether connect` string anywhere in the code.
