### WP-39: Display-backend seam (after 1.0, pending the owner)

- **Wave:** after 1.0. Not in any wave of the 1.0 pass, and not built until the owner pulls it in (the owner plans stereoscopic glasses; nothing about them is ruled yet).
- **Closes:** nothing. Refs the new issue "Display-backend seam: make link readiness display-neutral", labelled `after-1.0`.
- **Why:** after ruling 42 removes the tether, the link is still Quest-shaped: the watch machine is driven only by `adb track-devices`, so no other display can make the link ready; `LinkState` is adb-shaped (no headset, unauthorised, starting, ready, stopped); Start 3D is one hard-coded WiVRn command list; Setup, doctor and the Headset page are Quest-only; and the wrapper plays flat unless `LinkState::Ready`. Glasses need a display-neutral "a 3D display is ready" that the wrapper reads. This WP is the seam only, with Quest and WiVRn as the first backend. It does not pick glasses, a protocol or an output path.
- **Files (to be fixed when the owner pulls it in):** `crates/engine/src/link.rs`, `crates/engine/src/link/wivrn.rs`, `crates/engine/src/link/adb.rs`, `crates/engine/src/watch/machine.rs`, `crates/engine/src/watch/service.rs`, `crates/engine/src/watch/run.rs`, `crates/engine/src/api.rs`, `crates/engine/src/wrapper.rs`, `crates/engine/src/setup.rs`, `crates/engine/src/cli/doctor.rs`, and their tests.

**Shape (a sketch, not frozen)**
```rust
trait Display { fn detect(&mut self) -> Vec<DisplayEvent>; fn start(&mut self) -> Result<(), LinkError>; fn stop(&mut self) -> Result<(), LinkError>; fn state(&self) -> DisplayState; }
// QuestWivrn: the first backend (today's adb track-devices, link.rs, link/wivrn.rs)
```
The wrapper reads "a 3D display is ready" instead of `LinkState::Ready`. SPEC wording that is Quest-only ("giant fixed 3D TV in the Quest 2") stays until the owner rules on a second display.

**Open (owner's call):** whether this is before or after 1.0; which display comes second; whether the viewer needs a side-by-side window sink and the OpenXR output needs a different runtime for it (not checked against any specific glasses).

**Depends on:** WP-36 (the tether is gone), WP-12. **Owner device:** none until a second backend exists.

**Done-check:** to be written when the owner pulls this in.
